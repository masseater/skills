# 棚卸しして削る

## 進め方

1. 対象リポジトリの検証を回し、現状が通っていることを確かめる。落ちている箇所は単純化と切り分け、先に報告する
2. 検出ツールを回し、未使用と重複の候補の一覧を作る。あわせて、パッケージとモジュールの一覧と、依存の向きを出す
3. 候補を3つに分ける
   - 機械が断言できるもの。未使用の export、重複した実装
   - 統合の候補。常に一緒に変わるパッケージ同士、片方からしか使われていないモジュール、公開 API が実質は内部利用だけのパッケージ
   - 判断が要るもの。判断の持ち主に確認する
4. 進める順番は、機械が断言できるもの、統合、文書の順にする。段が終わるたびに検証を通す
5. PR は意味の単位で切る。統合は「移すだけ」の PR にし、移すついでに中身を直さない
6. 文書を通して見て、削った対象や統合前の名残への言及が残っていたら、判断に書き換えるか消す

## 統合の進め方

1. 統合先は、使われる側ではなく、変更の理由が近い側に寄せる
2. 依存の向きを確かめる。統合で循環ができるときは、その境界自体が間違っているので、判断の持ち主に上げる
3. ファイルを移し、import を直す。公開しているパッケージは、公開面（exports と型）が変わることを先に知らせる
4. 検証を通す。落ちたら、移した分だけを戻して切り分ける
