# simplify-repo

- 検査と上限は緩めない。当たったら中身を軽くする
- 工数は判断に入れない。完全に無視する
- 重複はコードの見た目でなく、内部で達成している機能で見る。見た目が違っても同じ機能なら、1つに抽象化する
- 分割しすぎたモジュールとパッケージは、迷ったら統合する側に倒す
- 公開面の変更は厭わない。publish 済みのパッケージ名の変更も含む。変わったら利用側も同じ変更で直し切る。止まって知らせない
- 測れていないものは、測れるようにすること自体を作業に含める
- 文書には判断だけ残す。利用箇所、ファイルの一覧、実装の写しは書かない
- 残すか迷ったものは「無くなると誰のどの判断が変わるか」で決める。答えが出なければ削る

## 達成状態

- 検証は基準を緩めずに通っている
- 検出で挙がった未使用と重複が残っていない。残したものには判断の理由がある
- 公開面の変更に追随していない利用側が残っていない
- 文書に残っているのは判断だけである

手順は [`棚卸しして削る`](usecases/simplify.md)。
