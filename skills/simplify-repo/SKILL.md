# simplify-repo

この skill が必要な理由は、リポジトリでは足すことには理由があっても削ることには理由が要ることにある。残す側に立つ仕組みがなければ全体は増える一方になり、古くなった記述が現行の事実の顔で残って読むエージェントの作業を誤らせる。

この skill で達成したい状態は、残っているものすべてが振る舞いか誰かの判断を変えている状態である。

## 規則

- 検査と上限は緩めない。検査に当たったら中身を軽くする
- 工数は判断に入れない。完全に無視する
- 重複はコードの見た目ではなく内部で達成している機能で判定する。見た目が違って同じ機能なら1つに抽象化する
- 分割しすぎたモジュールとパッケージは迷ったら統合する側に倒す
- 公開面の変更は厭わない。publish 済みのパッケージ名の変更も含む。変わったら利用側も同じ変更で直し切る。止まって知らせない
- 測れていないものは測れるようにすること自体を作業に含める
- 文書には判断だけ残す。利用箇所、ファイルの一覧、実装の写しは書かない
- 残すか迷ったものは「無くなると誰のどの判断が変わるか」で決める。答えが出なければ削る

## 達成状態

- 検証が基準を緩めずに通っている
- 検出で挙がった未使用と重複が残っていない
- 残したものには判断の理由がある
- 公開面の変更に追随していない利用側が残っていない
- 文書に残っているのは判断だけである

- [`棚卸しして削る`](usecases/simplify.md)。リポジトリ全体を対象に単純化する作業の進め方
