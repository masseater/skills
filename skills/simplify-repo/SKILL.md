# simplify-repo

- 検査と上限は緩めない。当たったら中身を軽くする
- 工数は判断に入れない。完全に無視する
- 重複は見た目でなく内部の機能で判定する。同じ機能なら1つに抽象化する
- 分割しすぎたモジュールとパッケージは迷ったら統合する
- 公開面の変更は厭わない。パッケージ名の変更も含む。利用側も同じ変更で直し切る。止まって知らせない
- 測れていないものは測れるようにすること自体を作業に含める
- 文書には判断だけ残す。利用箇所、ファイルの一覧、実装の写しは書かない
- 迷ったら「無くなると誰のどの判断が変わるか」で決める。答えが出なければ削る

## 達成状態

- 検証が基準を緩めずに通っている
- 検出の候補が理由なしに残っていない
- 公開面の変更に追随していない利用側が残っていない
- 文書に残っているのは判断だけ

手順は [`棚卸しして削る`](usecases/simplify.md)。
