# integrate

## この skill が必要な理由と達成したい状態

この skill が必要な理由は、新しい手段を入れても、旧手段が使える状態のまま残ることにある。作業者は手に馴染んだ旧手段や、近くの既存コードの書き方を真似るので、新しい手段を選ばせ続けるには毎回の注意と善意が要る。作業者の善意や労力を割くことで守られる仕組みは、存在しないのと同じである。新旧は並んで使われ続け、読み手はその違いに意味を探す。

この skill で達成したい状態は、新しい手段だけが使われ、旧手段は守ろうとしなくても使えないことである。

## やること

- 既存の同等の実装を探し、新しい手段へ移す。
- 新規コードで旧手段を使えないようにする。lint（`no-restricted-imports` など）、型、CI、依存関係の制約で止める。ドキュメント、慣習、レビューでの指摘は、作業者の善意と労力で守る仕組みにあたる。
- 新しい手段の使い方が複数あるときは、使い方も 1 つに揃える。読み手が書き方の違いに意味を探さずに済む。
- 導入で不要になった旧実装と依存を消す。
