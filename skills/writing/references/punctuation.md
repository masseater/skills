# 認識の単位を区切る句読点

句読点は、音読の息継ぎや口語の調子のためではなく、読者が文をどの単位で認識し、どの語句を結び付け、どこで意味を確定すべきかを示すために打つ。

読点は、条件、理由、対比、列挙、主節のように役割の異なる領域の境界に打つ。ひとまとまりの語句を途中で区切ると、読者は一度で認識できる内容を分解して組み直すことになる。役割の異なる領域を区切らずにつなぐと、どの条件や理由がどの結論にかかるかを推測させることになる。

句点は、1 つの主張、判断、因果関係が完了した場所に打つ。長くなったから切るのではなく、読者がそこで意味を確定できるかで決める。独立した主張は一文に詰め込まず、1 つの因果関係は読みやすさのためだけに分割しない。

学習データの説明文には「ではなく」の直後に読点を置く文が多く、AI はそこを反射的に区切る。短く構造の明白な文ではその読点に役割がなく、論理関係をいちいち指差す典型的な AI 文体になる。「〜ではなくて、」「〜よりも、」「〜するために、」「〜の場合は、」も同じで、誤読を防ぐ必要がない限り、短い修飾句や対比句の直後には読点を打たない。「長くなったから切るのではなく、読者がそこで意味を確定できるかで決める」のように「ではなく」の両側が述語を持つ対比は、役割の異なる領域の境界なので読点を打つ。

```
形式ではなく、文章が果たしている働きから判断する。
→ 形式ではなく文章が果たしている働きから判断する。
→ 形式ではなく文章の働きで判断する。
```

音読したときの間は確認の補助にはなるが、基準にはしない。話すときの間は話者で変わるが、文章で認識させるべき意味の関係は変わらない。

```
ユーザーが入力した、値を検証して、問題がなければ、保存する。
→ ユーザーが入力した値を検証し、問題がなければ保存する。
```

「ユーザーが入力した値」は 1 つの認識領域で、分割する理由がない。元の文は音読の間に機械的に打ったため、処理同士の関係ではなく単語の並びが分断されている。直した文では、値を検証する処理と、その結果を条件に保存する処理が区切られ、関係を一度で認識できる。

```
障害が起きた場合にデータを失わないために処理結果を先に保存する。
→ 障害が起きた場合にもデータを失わないよう、処理結果を先に保存する。
```

元の文は条件、目的、主となる処理が連続し、読者が境界を探すことになる。直した文では目的の領域と処理の領域が分かれ、何のために何をするかが明確になる。

読点を足しても複数の解釈が残るなら、句読点で無理に読ませず、語順や文を組み直す。句読点は書き手が整理した意味の構造を読者に同じ単位で認識させるためのもので、構造を後付けで作るものではない。

「A ではない。B である」のように、一文で表せる対比を短い文に割って重みや余韻を演出しない。句点は意味上独立した領域を分けるために使う。
