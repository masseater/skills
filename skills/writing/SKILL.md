# writing

## この skill が必要な理由と達成したい状態

この skill が必要な理由は、AI が文を、読者に何を判断させるかからではなく、学習した説明文の形から反射的に組み立てることにある。そのため理由が欠け、コードから導出できる陳腐化する情報が増え、反射的な読点が不自然な拍を作り、全文が同じ認知モードで平坦になる。この癖は読者を疲れさせ、大事な判断基準を埋もれさせる。

この skill で達成したい状態は、読者が一度読むだけで書き手の判断とその理由を受け取り、最後まで読み進められる文章になっていることである。

## 大原則

日本語の文章は philtzjp/skills の [`japanese`](https://github.com/philtzjp/skills/blob/main/.agents/skills/japanese/SKILL.md) に従う。この skill の規範は、その上に足すものである。

規範は、文型や禁止事項として機械的に当てはめるものではない。先に決めるのは「どう直すか」ではなく「その修正で文章の何を守るのか」であり、形式ではなく文章が果たしている働きで判断する。

### 緩急の設計

密度の高い文章が退屈になるのは、情報が多いからではなく、全文が同じ認知モードで書かれているからである。読者の認知モードを、観察する、迷う、確信する、確かめ直すのあいだで意図的に切り替え、常に「続きを読む理由」を残すことで、読み進める推進力を作る。

- 緩急は情報量の増減ではなく、認知モードの切替として設計する。観察、逡巡、断定、再観察の往復が 1 つの単位である。
- 文章には常に、答えの出ていない問い、裏の取れていない確信、あとで返すと約束した答えのような未回収の緊張を少なくとも 1 つ開いておく。緊張がすべて閉じた瞬間、読者は読むのをやめられる。
- 完成した結論を解説する声ではなく、考えながら進む当事者の声で書く。書き手が答えに至る過程の再演が、読者の思考の再演になる。
- 拍、緊張、緩みの材料は、対象世界の出来事、データ、発言、語り手の判断状態といった状況の側からだけ取る。場面のない説明文では、対象そのものの性質と、読者が抱く推論や反問が状況にあたる。状況に材料がない位置は、何も足さず平坦なまま残す。本文自身を話題にした文でリズムを作るのは、規範の違反である。
- 装置は内容で実現し、宣言しない。「先に答えを半分だけ置く」のように、これからやる操作を述べた文はそれ自体が駄文である。装置が機能していれば、読者は装置の存在に気づかない。
- 拍を作るために文を削らない。範囲、観点、比較軸、未確定事項といった導入に必要な文脈共有を削って短くするのは、緩急ではなく欠落である。密度を上げる編集は、共有済みの文脈の上でだけ行う。

文、段落、章の単位での実現と、駄文の見分け方、執筆後の点検は [`rhythm`](references/rhythm.md) にある。

## 規範

`references/` は説明文の規範である。日本語の説明文を書くたびに読む。

- [`purpose-and-reason`](references/purpose-and-reason.md): そうする目的を書く。動作の説明は理由の代わりにならず、技術で完結する理由はプロダクトの要件まで遡る。
- [`no-perishable-information`](references/no-perishable-information.md): コードや設定から導出できる個数、名称、配置を文書に複製せず、正本を参照する。
- [`punctuation`](references/punctuation.md): 句読点は音読の間ではなく、読者が意味を認識する単位の境界に打つ。
- [`purpose-before-means`](references/purpose-before-means.md): 手段と目的があるときは目的を先に書き、目的を括弧に入れない。
- [`headings`](references/headings.md): 見出しは体言止めにし、敬語や「〜します」で書かない。

## 用途

`usecases/` は特定の文章を書くときの手順である。当てはまるときだけ読む。

- [`novel`](usecases/novel.md): 小説や物語を書く、増補する、改稿するとき。説明文の規範はそのまま当てはめない。
- [`zenn-article`](usecases/zenn-article.md): 会話の内容や指定されたトピックから Zenn の技術記事を書き、masseater/zenn-article に PR を出す。ユーザーに頼まれたときだけ読み、PR は承認を得てから出す。
