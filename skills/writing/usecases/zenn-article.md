# Zenn 記事の作成

会話の内容や指定されたトピックから Zenn の技術記事を書き、ユーザーのレビューを経て `masseater/zenn-article` に PR を出す。

## 手順

1. 素材を決める。トピックの指定があればそれを主題にし、会話は参照材料として使う。指定がなければ、このセッションの技術的な内容を記事に再構成する。会話をそのまま貼らない。
2. 下の形式と文体で記事を書く。文章はこの skill の規範に従う。
3. 記事をユーザーに見せ、承認されるまでフィードバックを反映する。PR は外部リポジトリへの公開を伴うので、承認を得るまで投稿に進まない。
4. 下の投稿の手順でリポジトリに PR を出す。

## リポジトリ

GitHub の `masseater/zenn-article` で、default branch は `master` である。記事は `articles/`、画像は `images/` に置く。

ローカルパスは `${CLAUDE_PLUGIN_DATA}/repo-path.txt` から読む。なければユーザーに聞き、そのファイルに保存して次回から使う。plugin の更新で消えないよう、保存先は `${CLAUDE_PLUGIN_DATA}` にする。

## 形式

```yaml
---
title: "記事タイトル"
emoji: "内容に合う絵文字 1 つ"
type: "tech"
topics: [既存の Zenn タグを優先、最大 5 個]
published: false
---
```

- 公開するかどうかはユーザーが Zenn 上で決めるので、`published` は常に `false` にする。
- ファイル名は `claude-code-plugin-intro.md` のように内容を表すケバブケースの slug にし、ランダムなハッシュは使わない。
- frontmatter の直後に要点 1 行から 3 行の「tl;dr」、背景と動機の「はじめに」、本文、振り返りと次の一手の「おわりに」または「まとめ」の順に構成する。節は短くし、長くなったら分ける。

## 文体

著者の過去記事から抽出した文体である。

- 日本語で書く。`Claude Code`、`git worktree`、`Bun` のような技術用語、ライブラリ名、コマンドは英語のまま書く。
- 読者は Claude Code、TypeScript、Git、React のような主要なツールを知っている前提で書き、「X は Y をするツールです」のような導入は省く。文脈上必要でも 1 行までにし、説明するのは記事の中心になるニッチなツールだけにする。
- 書くのは「著者が何をして、なぜそうして、何が分かったか」であり、ツールの使い方の解説記事にはしない。
- です・ます調を基本に、くだけた表現を混ぜる。「Claude Code、使ってますよね？ 使ってる前提で詳しい説明は省きます」のように読者に直接話しかけてよい。
- 「これはなかなか面白い結果だと思いました」「効いてるかは分かりません。気分です」のような率直な感想を書く。本当に面白いところでだけ、「なんだこれ……まあいいか」のような自虐やツッコミを入れる。
- 本題から書き始める。「〜をご紹介したいと思います」のような丁寧すぎる前置きや、「見ていきましょう！」「いかがでしたか？」のような定型句は使わない。
- 散文の方が伝わる内容は散文で書き、箇条書きは本当に列挙のときだけにする。
- 分からないことは分からないと書く。
- コードブロックには言語を指定する。実際のソースへの GitHub リンクを積極的に入れ、構成の説明で図のほうが伝わるときは mermaid を使う。
- `:::details`、`:::message`、URL 単独行の自動埋め込みのような Zenn 記法を活用する。
- 画像が必要なら、ユーザーに Zenn の画像アップロード機能を使うよう伝える。ローカル画像は `images/` に置く。

## 投稿

```bash
cd <repo-path>
git checkout master && git pull
git checkout -b article/<slug>
# articles/<slug>.md を作成
git add articles/<slug>.md
git commit -m "Add article: <title>"
git push -u origin article/<slug>
gh pr create --title "Add article: <title>" --body "- <記事の要約>
- published: false（下書き）"
```

作成した PR の URL をユーザーに伝える。
