# README.md を書く

README.md を書く、直すときの手順である。README の読み手は、リポジトリを初めて開いた人間である。AI もコンテキストとして読むが、AI への指示は AGENTS.md や CLAUDE.md に置き、README には書かない。それらの書き方は ai-context に従う。

- 冒頭の数行で、何をするもので誰のためのものかを伝える
- 使い始めるまでの手順を、そのまま実行できる形で書く
- コードや設定から導出できる情報は写さず、指し示す

## 読み手

README を開く人は、このリポジトリを使うか、関わるかを決めようとしている。前提知識はなく、上から順に読み、決められるだけの材料がそろった時点で読むのをやめる。冒頭で判断できなければ、続きは読まれずに閉じられる。

AI 向けの指示や作業の決まりを README に混ぜると、人間は自分に関係のない文を読み飛ばしながら、必要な情報を探すことになる。

## 冒頭の要約

題と冒頭だけで、使うかどうかを決められるようにする。

- 一文目で、何をするものかを言う。作った経緯や技術の選定から始めない
- 誰の、どんな問題を解くのかを書く
- 公開先やインストール先があれば、冒頭の近くに URL を置く

## 導入の手順

導入の手順は、読み手が手を動かしながら読む節である。

- 前提になるランタイムやアカウントを、手順より先に書く
- コマンドは、コピーしてそのまま動く形で書く
- 最小の動く例を 1 つ示し、動いたことを確かめる方法を書く
- 手順の途中に背景や設計の説明を挟まない。説明が要るなら節を分けてリンクする

## 書かないこと

README に書くと腐る情報や、ほかに置き場所がある情報は書かない。

- AI への指示や作業の決まりは AGENTS.md や CLAUDE.md に置く
- ディレクトリ構成、API の一覧、設定項目のように、コードから導出できる情報は no-perishable-information に従って指し示す
- 設計の理由はコミットメッセージや DESIGN.md に置く
