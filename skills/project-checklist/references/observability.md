# observability

本番で起きたことを外から読めるかを確かめる。読めないと、不具合のたびに推測で直すことになる。考え方は [Google SRE の Production Readiness Review](https://sre.google/sre-book/evolving-sre-engagement-model/) に従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| 本番の 1 件のリクエストを追えるか | 本番で失敗したリクエストを 1 件選び、ログとスパンからたどる | 再デプロイせずに、どこで何が起きたかが分かる |
| 時間かお金を使う処理の計測 | 外部 API、モデル、DB、子プロセスを呼ぶ箇所に、スパンがあるかを探す | すべてスパンになっている |
| 壊れたことに気づけるか | エラー率や失敗の通知の設定を探す | 壊れたことが、人が見る場所に届く |
| CI の実行の記録 | ワークフローの最後に、ジョブとステップの時間を送るジョブがあるかを見る | ジョブとステップの時間が残る |
