# requirements

誰が何のために使い、どれだけの規模になるかを確かめる。決まっていないと、ほかの領域の満たす状態が決まらない。考え方は [AWS Well-Architected Framework](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html) の、設計を負荷と要件から決める考え方に従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| 誰が何のために使うか | README と docs を読む | 使う人と、その人ができることが書いてある |
| 想定する規模 | 規模の記述と、本番のアクセス解析の値を見比べる | 次の規模の利用者数・リクエスト数・データ量が数字で書いてあり、本番の値と取った日付が添えてある |

今の規模ではなく次の規模を書くのは、設計を変えるより先に規模が変わるからである。
