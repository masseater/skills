# requirements

利用者と目的、想定する規模が決まっていないと、ほかの領域の充足条件も決まらない。まずこの三つを確認する。設計は負荷と要件から決めるという [AWS Well-Architected Framework](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html) の考え方に沿う。

| 確認する事項 | 現状の確認方法 | 充足条件 |
| --- | --- | --- |
| 利用者と目的 | README と docs を読む | 誰が使い、何ができるかが書いてある |
| 想定する規模 | 規模の記述と、本番のアクセス解析の数値を比較する | 次の段階の利用者数、リクエスト数、データ量が数値で書いてあり、本番の実測値と取得日が添えてある |

規模は設計を変更するより先に変わるので、書くのは現在の規模ではなく次の段階の規模である。
