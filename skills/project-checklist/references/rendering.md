# rendering

ページごとのレンダリングの方式を確かめる。方式を決めないと、フレームワークの既定のまま、全員に同じページまでリクエストのたびにサーバーで作られる。方式の分け方は web.dev の [Rendering on the Web](https://web.dev/articles/rendering-on-the-web) に従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| ページごとの方式 | ルートの設定（プリレンダー、SSR、クライアントだけ）と、ビルド出力に各ページの HTML があるかを見る | 中身が全員に同じページは、ビルド時に HTML になっている。閲覧者やリクエストごとに変わる部分だけが、サーバーかクライアントで作られる。変わる部分をクライアントで作るページは、その殻がビルド時に HTML になっていればよい |
| 静的なページでサーバーの処理が動いていないか | ホスティングの分析 API かダッシュボードで、サーバーの処理の起動数を、本番でページを何度か開く前後で比べる | 静的なページを開いても、サーバーの処理が動かない |

ビルド出力に HTML があるだけでは足りない。プリレンダーした HTML をサーバーの処理を通して返していれば、リクエストのたびにサーバーが動く。
