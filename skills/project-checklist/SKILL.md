# project-checklist

プロジェクトが設計で考えるべきことを、項目ごとに今どうなっているかを実物で確かめて判定する。

- 各項目は、今の状態を確かめ、満たす状態と比べて判定する
- 判定には、見た場所と見た結果を添える
- 判定は「満たす」「欠け」「未確認」「対象外」のどれかにする

## この skill が必要な理由と達成したい状態

この skill が必要な理由は、設計で考えるべきことの多くが、考えなくてもプロジェクトが動いてしまうことにある。公開範囲、レンダリングの方式、費用、性能、アクセシビリティ、復旧の手段は、決めなければ、テンプレートやフレームワークの既定がそのまま答えになる。既定の答えでもビルドもテストも通り、画面も表示されるので、誰も決めていないことに気づかない。さらに、決めたつもりのことと動いている実物はずれる。設定ファイルや設計メモを読んだだけでは、本番で何が起きているかは分からない。こうして誰も選んでいない設計のまま公開され、問題は請求、漏えい、遅さ、データの消失として後から見つかる。

この skill で達成したい状態は、設計で考えるべきことのすべてについて、そのプロジェクトが今どうなっているかを、実物を見た根拠つきで言い切れていることである。

## 判定の作り方

- 今の状態は、本番で動いているもの、ビルドの出力、リポジトリのファイルの順に見る。本番に近いものほど、意図ではなく事実を表すからである。本番の確かめ方は measure-dont-guess に従う
- 方針や設定が書いてあるだけでは「満たす」にしない。書いてあっても効いていないことがある
- 数値で決まる項目は、測った値で判定する
- 満たす状態は、プロジェクトの AGENTS.md や CLAUDE.md に決まりがあれば、そちらを使う。そのプロジェクトで下した判断が、一般的な基準より優先するからである
- 見られなかった項目は「未確認」とし、見られなかった理由を書く。推測で埋めると、確かめていないことが確かめたことと同じ顔で残る
- 当てはまらない項目は「対象外」とし、プロジェクトの実物から言える理由を書く。理由の書けない対象外は欠けである

## 項目

次もすべて読むこと。領域ごとに、確かめること、今の状態の確かめ方、満たす状態を表にしている。

- [`requirements`](references/requirements.md)。誰が何のために使うかと、想定する規模
- [`access`](references/access.md)。ページと API ごとの公開範囲と、認証・権限の検査
- [`rendering`](references/rendering.md)。ページごとのレンダリングの方式
- [`data`](references/data.md)。データの置き場所、スキーマの変え方、キャッシュ
- [`security`](references/security.md)。秘密情報、依存の脆弱性、レスポンスヘッダー、動的な検査、レート制限
- [`cost`](references/cost.md)。1 回のアクセスで課金されるもの、暴走の上限、実際の請求
- [`performance`](references/performance.md)。Web Vitals とサーバーの応答時間
- [`search-and-sharing`](references/search-and-sharing.md)。検索に載せるか、載せるページの中身、共有したときの表示
- [`accessibility`](references/accessibility.md)。機械で見つかる違反と、キーボードだけでの操作
- [`observability`](references/observability.md)。本番のリクエストを追えるか、計測、壊れたことに気づけるか
- [`reliability`](references/reliability.md)。データの復旧、リソースの作り直し、外部呼び出しの失敗
- [`delivery`](references/delivery.md)。検査とデプロイの経路、前の版への戻し方、環境変数
- [`dependencies`](references/dependencies.md)。依存の選び方とライセンス、他人の素材
- [`privacy`](references/privacy.md)。集めている個人情報と、その消え方
- [`publishing`](references/publishing.md)。公開しているものの一覧、URL の変更、終わらせ方
