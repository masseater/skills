# project-checklist

プロジェクトが設計で考えるべきことを、項目ごとに今どうなっているかを実物で確かめて判定するための一覧である。

- 各項目は、決まっているか、実物がどうなっているか、満たす状態に届いているかで見る
- 判定には、見た場所と見た結果を添える
- 見られなかった項目は「未確認」とし、見られなかった理由を書く
- 当てはまらない項目は「対象外」とし、プロジェクトの実物から言える理由を書く。理由の書けない対象外は欠けである

## この skill が必要な理由と達成したい状態

この skill が必要な理由は、設計で考えるべきことの多くが、考えなくてもプロジェクトが動いてしまうことにある。公開範囲、レンダリングの方式、費用、性能、アクセシビリティ、復旧の手段は、決めなければ、テンプレートやフレームワークの既定がそのまま答えになる。既定の答えでもビルドもテストも通り、画面も表示されるので、誰も決めていないことに気づかない。さらに、決めたつもりのことと動いている実物はずれる。設定ファイルや設計メモを読んだだけでは、本番で何が起きているかは分からない。こうして、誰も選んでいない設計のまま公開され、問題は請求、漏えい、遅さ、データの消失として後から見つかる。

この skill で達成したい状態は、設計で考えるべきことのすべてについて、そのプロジェクトが今どうなっているかを、実物を見た根拠つきで言い切れていることである。

## 判定の作り方

- 今の状態は、本番で動いているもの、ビルドの出力、リポジトリのファイルの順に見る。本番に近いものほど、意図ではなく事実を表すからである。本番の確かめ方は measure-dont-guess に従う
- 書かれた方針や設定だけで「満たす」としない。方針は書いてあるだけで効いていないことがある
- 数値で決まる項目は、数値を測って書く。「速い」「安い」は判定にしない

## 項目

各表の「今の状態の確かめ方」で今を見て、「満たす状態」と比べる。

### 要件と規模

[AWS Well-Architected Framework](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html) の、設計を負荷と要件から決める考え方に従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| 誰が何のために使うか | README と docs を読む | 使う人と、その人ができることが書いてある |
| 想定する規模 | README や docs の規模の記述と、本番のアクセス解析の値を見比べる | 次の規模の利用者数・リクエスト数・データ量が数字で書いてあり、本番の値と取った日付が添えてある |

### 公開範囲と認証

[OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/) の認証とアクセス制御の章に従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| ページと API ごとに誰が見られるか | ルーティングの定義と認証の設定から、全ページと全 API を公開・本人だけ・ログインした人に分けた一覧を作る | 全ページと全 API が、どれかに分けてある |
| 非公開のものが本当に閉じているか | 本番の非公開の URL と、プラットフォームが既定で発行する URL に、ログインせずにリクエストする | 中身が返らない |
| API ごとの権限の検査 | 各 API のハンドラーで、呼び出し元の権限を確かめる処理を探す。ログインしていない状態と、他人の権限での呼び出しのテストを探す | すべての API が権限を確かめ、そのテストがある |

### レンダリングと配信

方式の分け方は web.dev の [Rendering on the Web](https://web.dev/articles/rendering-on-the-web) に従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| ページごとの方式 | ルートの設定（プリレンダー、SSR、クライアントだけ）と、ビルド出力に各ページの HTML があるかを見る | 中身が全員に同じページは、ビルド時に HTML になっている。閲覧者やリクエストごとに変わる部分だけが、サーバーかクライアントで作られる |
| 静的なページでサーバーの処理が動いていないか | 本番でページを開き、サーバーの起動数やログが増えるかを見る | 静的なページを開いても、サーバーの処理が動かない |

### データと保存先

[The Twelve-Factor App](https://12factor.net/) の backing services と admin processes に従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| データごとの置き場所 | インフラの定義とスキーマから、データの種類ごとの保存先の一覧を作る | 1 つのデータの正本が 1 か所にある |
| スキーマの変え方 | マイグレーションのファイルと、スキーマとの差分の検査を見る | スキーマはマイグレーションを通してだけ変わり、差分が検査で落ちる |
| 閲覧者ごとのデータとキャッシュ | キャッシュのキーと、キャッシュに入れる値を見る | 閲覧者ごとに変わる値が、閲覧者をまたぐキャッシュに入らない |

### セキュリティ

[OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/) と [OWASP Top 10](https://owasp.org/www-project-top-ten/) に従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| 秘密情報の置き場所 | gitleaks のような秘密情報の検出を、リポジトリの全履歴に掛ける | 検出が無い。秘密情報はシークレットの保管先にだけある |
| 依存の脆弱性 | パッケージマネージャーの audit を実行する | 勧告が無い。修正版の無い勧告だけが、理由つきで除外されている |
| レスポンスヘッダー | 本番の各ページに `curl -I` でリクエストし、CSP、HSTS、X-Content-Type-Options、Referrer-Policy、Permissions-Policy を見る | すべて付いている |
| 動的な脆弱性検査 | 本番に ZAP のスキャンを掛ける | 警告も含めてアラートが無い |
| 書き込みと認証の口への大量のリクエスト | レート制限の設定を探す | 書き込み、認証、公開 API の前にレート制限がある |

### 費用

[AWS Well-Architected Framework](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html) のコスト最適化の柱に従う。Cloudflare に載せるものは cloudflare-caution にも従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| 1 回のアクセスで課金されるもの | 公開ページを開いたときに出るリクエストをブラウザーの開発者ツールで全部挙げ、それぞれがどのサービスのどの課金単位に当たるかを書く | 外部公開するサイトの配信に、使用量で課金される経路が無い。「無料枠に収まる」は満たす理由にしない |
| 暴走したときの上限 | 実行時間の上限、再試行の回数の上限、予算アラートの設定を見る | 無限ループや再試行のバグが、上限で止まる |
| 実際の請求 | 請求のダッシュボードで、課金単位ごとの使用量を見る | 見積もりと本番の使用量がずれていない |

### 性能

[Web Vitals](https://web.dev/articles/vitals) に従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| LCP・INP・CLS | 本番の各ページの読み込みと、ページ内のリンクを押した遷移を、Lighthouse の user flow で複数回測る | 各ステップの中央値で、Lighthouse の合格点（0.9）に届いている |
| FCP・TTFB・TBT | 同じ計測の結果を見る | 値が記録されている |
| サーバーの応答時間 | 本番のスパンかログから、API ごとの p95 を出す | 要件の時間に収まっている |

### 検索と共有

[Google 検索の基本事項](https://developers.google.com/search/docs/essentials) と [Open Graph protocol](https://ogp.me/) に従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| 検索に載せるかどうか | 本番の `robots.txt` と、各ページの `meta name="robots"` と `X-Robots-Tag` を見る | 載せるページと載せないページが決まっていて、そのとおりになっている |
| 載せるページの中身 | 本番の HTML を `curl` で取り、本文、title、description、canonical があるかを見る | JavaScript を動かさなくても、中身とメタデータが HTML にある |
| 共有したときの表示 | 本番の HTML の OGP のタグと、その画像の URL を開く | og:title、og:description、og:image があり、画像が返る |

### アクセシビリティ

[WCAG 2.2](https://www.w3.org/TR/WCAG22/) の AA に従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| 機械で見つかる違反 | 本番の各ページに Lighthouse のアクセシビリティ監査か axe を掛ける | 違反が無い |
| キーボードだけでの操作 | 主な操作の流れを、キーボードだけでたどる | すべての操作ができ、フォーカスの位置が見える |

### 観測と運用

[Google SRE の Production Readiness Review](https://sre.google/sre-book/evolving-sre-engagement-model/) に従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| 本番の 1 件のリクエストを追えるか | 本番で失敗したリクエストを 1 件選び、ログとスパンからたどる | 再デプロイせずに、どこで何が起きたかが分かる |
| 時間かお金を使う処理の計測 | 外部 API、モデル、DB、子プロセスを呼ぶ箇所に、スパンがあるかを探す | すべてスパンになっている |
| 壊れたことに気づけるか | エラー率や失敗の通知の設定を探す | 壊れたことが、人が見る場所に届く |
| CI の実行の記録 | ワークフローの最後に、実行時間を送るジョブがあるかを見る | ジョブとステップの時間が残る |

### 信頼性と復旧

[AWS Well-Architected Framework](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html) の信頼性の柱に従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| データの復旧 | データストアのバックアップかポイントインタイムリカバリの設定と、復元した記録を見る | 復元の手段があり、一度復元して戻せている |
| リソースの作り直し | インフラの定義で、名前を変えると作り直されるリソースを探す | データを持つリソースが、意図せず作り直されない |
| 外部呼び出しの失敗 | 外部 API の呼び出しに、タイムアウトと再試行の上限があるかを見る | どちらもある。再試行される処理は冪等である |

### CI とデプロイ

[The Twelve-Factor App](https://12factor.net/) の build, release, run と config に従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| 検査がどこで動くか | ワークフローとフックの設定を見て、main の最新の実行結果を見る | main への push で検査が動き、最新の実行が通っている |
| デプロイの経路 | ワークフローのデプロイのジョブを見る | 手元の環境に頼らず、検査を通ったものだけがデプロイされる |
| 前の版への戻し方 | 前の版をデプロイし直す手順を探す | 手順があり、一度戻せている |
| 環境変数 | `.env.example` とワークフローの環境変数を見る | 環境ごとに変わる値だけが環境変数で、変わらない値はコードか設定にある |

### 依存とライセンス

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| 依存の選び方 | 自前で書いた処理のうち、既存のライブラリで置き換えられるものを探す | dont-it-yourself に従っている |
| 依存のライセンス | ライセンスの一覧を出すツールで、依存のライセンスを挙げる | 配布の形と両立する |
| 他人の素材 | 画像、音声、文章の出どころと、その利用条件を見る | 公開してよい素材だけが公開リポジトリと公開先にある |

### 個人情報

[個人情報保護委員会の事業者向けガイドライン](https://www.ppc.go.jp/personalinfo/legal/) に従う。

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| 何を集めているか | スキーマ、ログ、解析のタグから、個人に関わる値の一覧を作る | 一覧があり、それぞれの使い道が決まっている |
| いつ消えるか | 保存期間の設定と、削除の処理を探す | 保存期間と消し方が決まり、そのとおりに動く |

### 公開先と終わらせ方

| 確かめること | 今の状態の確かめ方 | 満たす状態 |
| --- | --- | --- |
| 公開しているもの | README の公開先の一覧と、DNS、デプロイ先、パッケージの公開先を見比べる | 一覧と実物が一致している |
| URL の変更 | 移動したページのリダイレクトの設定を探す | 古い URL から新しい URL へ移る |
| 終わらせ方 | インフラの定義と state から、作ったリソースの一覧を作る | 消す手順で、DNS、認証の設定、公開先の一覧まで消える |
