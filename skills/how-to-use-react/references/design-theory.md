# 宣言的 UI とトランジション

大本: https://speakerdeck.com/uhyo/react-no-sekkeiron

## 保証

- 一貫性: 変化前と変化後の UI が同居しない。
- 即時性: ステート更新が最優先で画面に出る。

緩めるときは、その緩和を API で宣言する。

| 緩和 | API | 使うとき |
| --- | --- | --- |
| 即時性 | `useTransition` / `startTransition` | イベントで起きる画面の変化のほぼ全部 |
| 一貫性 | `useDeferredValue` | 入力と重い一覧を同じコミットに載せなくてよいとき |

すでに起きた外部の変化に React の状態を合わせる更新だけを緊急（即時性を外さない更新）にする。

## Suspense

境界は「一緒に出す／別々に出してよい」という独立性の制約である。再サスペンドでスケルトンに戻すより、トランジションで古い画面を残す。

## トランジションの中で

- トランジション中にすぐ見せたい表示は `useOptimistic`。pending の演出にも使う。
- 順番が仕様の更新列は同じ `scope.id` の `useMutation` に載せ、操作を止めない（`action-queue.md`）。

`isPending` は「その操作が起こした遷移の最中」である。`await` が終わっても、サスペンドが残っていればトランジションは続く。
