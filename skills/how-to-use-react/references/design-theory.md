# 宣言的 UI とトランジション

React は一貫性と即時性を保証する。緩めるときは、その緩和を API で宣言する。

- 一貫性: 変化前と変化後の UI は、同じ画面に同居しない
- 即時性: ステートの更新は、最優先で画面に反映される
- すでに起きた外部の変化に React の状態を合わせる更新だけは、遅らせずに反映する

| 緩和 | API | 使うとき |
| --- | --- | --- |
| 即時性 | `useTransition` と `startTransition` | イベントで起きる画面の変化のほぼ全部 |
| 一貫性 | `useDeferredValue` | 入力と重い一覧を同じコミットに載せなくてよいとき |

## Suspense

境界は、一緒に出すか別々に出してよいかを分ける区切りである。再サスペンドでスケルトンに戻すより、トランジションで古い画面を残す。

## トランジションの中で

- トランジション中にすぐ見せたい表示は `useOptimistic` で出す。pending の演出にも使う
- 順番が仕様の更新列は同じ `scope.id` の `useMutation` に載せ、操作を止めない。[`action-queue`](action-queue.md) も読むこと

`isPending` は、その操作が起こした遷移が続いているあいだ true になる。`await` が終わっても、サスペンドが残っていればトランジションは続く。
