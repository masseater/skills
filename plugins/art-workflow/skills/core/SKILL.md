# core

引数: `$ARGUMENTS`

作品のフォルダは `art/<作品名>/` で、この段階は `core.md` を書く。

## なぜこのスキルが必要で、どのような状態を目指すべきか

このスキルが必要な理由は、AI が参考画像を渡されると、その形、色、服装、画風を言葉に写すからだ。写した言葉から作った姿は参考の言い換えになり、持ち主の作品にならない。また用途を先に決めると、その用途で作りやすい形が姿を縛る。

このスキルが目指す状態は、作品が何であるかを、参考の見た目を含まない言葉だけで持っている状態である。そこから参考と似ても似つかない姿に着地してよい。

## 抜き出し方

- 参考ごとに、持ち主が惹かれている理由を見た目から概念へ引き上げる。「赤いベレー帽」ではなく、それが生んでいる「冬の外出の浮かれた気分」を書く。
- 概念は、テーマ、感情、モチーフ、形の言語（丸い、尖った、重い、軽いなど）、見る人に起きてほしいことに分けて書く。後の段階はこの分け方で案を振る。
- 核を 1 文で書く。案を選ぶとき、迷ったらこの 1 文に近い方を取る。
- 捨てた見た目（形、色、配置、服装、画風）を「捨てた見た目」として列挙する。後の段階で案が参考に戻ったとき、それと分かるようにするため。
- 対象の種類を、キャラクター、小物、背景・場所、イラスト、世界観から 1 つ書く。参照用の図の組はこれで決まる。
- 用途（3D、Live2D など）は聞かず、書かない。

## 進め方

- 参考を見て、`core.md` の案を先に書いて見せ、持ち主の反応で直す。質問を並べない。持ち主は問いの一覧より、案への反応の方が判断を出しやすい。
- 参考画像は `images/` に置いてパスを `core.md` の末尾に書く。後の段階のプロンプトには添付しない。
