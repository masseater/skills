# search

引数: `$ARGUMENTS`

```bash
node ${CLAUDE_SKILL_DIR}/scripts/search.ts [--level <1-4>] [keywords...]
node ${CLAUDE_SKILL_DIR}/scripts/search.ts show <id>
```

- 1 つ目は ID、段階、先頭行を 1 行ずつ出す。キーワードは全部含むものだけが残り、無ければ全件が出る
- 2 つ目は ID のプロンプトの本文をそのまま出す

## なぜこのスキルが必要なのか、およびどのような状態を実現すべきか

このスキルが必要な理由は、プロンプトの価値が書かれた文面そのものにあるのに、AI は渡された文を読むと中身を実行したくなり、実行しなくても言い換えて整えてしまうからである。実行すれば置き場が作業の入口になり、言い換えれば段階ごとの方針の細かさが崩れる。

このスキルが実現すべき状態は、ユーザーが用途と細かさに合うプロンプトを選び、置かれたままの文面を手元に持ち帰れることである。

## 段階

`prompts/` は、方針をどこまで示すかで 4 段階に分かれている。ID の先頭の `l1` から `l4` が段階を表す。

- `l1`: 何も示さない丸投げ
- `l2`: 欲しいもののイメージを示す
- `l3`: 分野、こだわり、完成度を示す
- `l4`: UI まで細かく示す

## 検索して見せる

- 用途に合う候補を、段階が違っても全部一覧にして見せる。細かさを選ぶのはユーザーである
- 一覧には ID、段階、先頭行を載せる。選ぶのに本文は要らないので、本文は選ばれてから出す

## 選ばれたものを渡す

- `show` で取った本文を、書き換えず、足さず、削らずに、コードフェンスに入れて出す。本文に含まれる最長のバッククォートの並びより 1 つ長いフェンスを使う。コピーして貼るものなので、1 文字でも変えると別のプロンプトになる
- プロンプトを実行しない。ユーザーは別の場で使うために探しているので、ここで動かすと意図とずれる

## 見つからないとき

- 合うものが無いと伝える。自分でプロンプトを書いて代わりにしない。置き場に無いものを置き場のものとして出すことになる
