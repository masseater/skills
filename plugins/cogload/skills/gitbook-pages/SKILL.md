# gitbook-pages

## なぜこのスキルが必要で、どのような状態を目指すべきか

このスキルが必要な理由は、AI が HTML の資料を作るたびに、レイアウトとスタイルを一から書くからだ。ページごとに手で書くと、サイドバーや見た目がページ間でずれ、資料ごとに違う既定値の UI になり、中身より HTML の組み立てに手間を使う。

このスキルが目指す状態は、AI が中身の Markdown だけを書き、どの資料も同じ構造と見た目で、サイドバーの項目ごとに別のページとして読めることである。

## 書く

資料ごとにディレクトリを 1 つ作り、`SUMMARY.md` と各ページの Markdown を置く。`SUMMARY.md` の順序とグループが、そのままサイドバーと前後のページへのリンクになる。

```markdown
# 資料の名前

## グループの名前

* [概要](overview.md)
  * [詳細](overview/detail.md)
* [手順](steps.md)
```

- 最初に並べたページが Artifact の本体になる。持ち主が最初に読むページを先頭に置く。
- 各ページは `# ページの名前` で始める。`##` と `###` が右の「このページ」に並ぶので、見出しは目次として読める語にする。
- 書けるのは GFM の表、箇条書き、番号付きリスト、コードブロック、リンク、画像と、次の 2 つである。HTML を書くと文字のまま表示される。
  - 図は言語名を `mermaid` にしたコードブロックで書く。Artifact が描画する。
  - 注釈は `> [!NOTE]`、`> [!TIP]`、`> [!IMPORTANT]`、`> [!WARNING]`、`> [!CAUTION]` で書く。
- ページ間のリンクは `.md` のパスで書く。スクリプトが公開後のファイル名に直し、`SUMMARY.md` にないページへのリンクを止めるので、リンク切れが公開されない。

## 公開する

Markdown はスクラッチパッドに置き、このスキルのディレクトリにある `scripts/build.ts` を Node で実行する。Artifact は作業ディレクトリかスクラッチパッドの下のファイルしか公開できない。

```sh
node <スキルのディレクトリ>/scripts/build.ts <資料のディレクトリ> <出力先>
```

スクリプトが出力する JSON の `file_path` と `files` を、そのまま Artifact の publish に渡す。直すときは Markdown を直して同じ出力先にもう一度ビルドし、同じ `file_path` で publish する。`file_path` が変わると別の URL の Artifact になる。
