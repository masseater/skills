# gitbook-slides

## なぜこのスキルが必要で、どのような状態を目指すべきか

このスキルが必要な理由は、AI がスライドを渡すたびに、ページ送り、一覧、スピーカーノート、PDF の出し方を一から組むからだ。組み方がデッキごとに変わるので、持ち主はデッキを開くたびに操作を覚え直す。1 つのページを縦に流す形で渡すと、今どのスライドを読んでいるかも持ち主が覚えておくことになる。

このスキルが目指す状態は、どのデッキも同じ画面と操作で開け、持ち主が今いるスライドを見失わず、発表、読み物、PDF のどれにも同じ 1 つのファイルで使えることである。

## 書く

デッキごとにディレクトリを 1 つ作り、`SUMMARY.md`、スライドごとの HTML、任意で `deck.css` を置く。[examples/](examples/) の下のデッキがそのまま動く見本で、それぞれの `preview.png` に全スライドが並んでいる。

```markdown
# デッキの名前

* [表紙](cover.html)

## グループの名前

* [スライドの名前](problem.html)
```

- `SUMMARY.md` の順序がスライドの順序になり、`##` が左の一覧のグループになる。リンクの文字が一覧と前後リンクに出るので、スライドの中身を示す語にする。
- スライドのファイルは `<section>` 1 つだけにする。`class` を付けると、そのスライドにだけ `deck.css` の規則を当てられる。
- スライドは 1920×1080 px の固定の画面として書く。表示の大きさはスクリプトが合わせるので、px のまま書けば画面幅に関係なく同じ配置になる。
- 背景、余白、文字の大きさは `deck.css` に `.slide` の規則として書く。どのデッキも同じ見た目になるのを防ぐため、既定の見た目はスライドに付けていない。
- そのスライドで一番伝えたい 1 文は `<p class="message">` に書く。スライドの下端に固定され、図や本文の量に関係なく同じ位置に出る。位置は `--message-inset` と `--message-bottom`、見た目は `deck.css` の `.slide .message` で決める。 伝えたいことだけを見せるスライドは `<section class="statement">` に `<p class="message">` だけを書く。メッセージは下端でなく上下の中央に置かれる。
- スピーカーノートは `<aside class="notes">` に書く。スライドの下にだけ出て、発表の画面と PDF には出ない。
- 図は `<svg>` をスライドに直接書く。`<img>` で読んだ SVG にはデッキのフォントが効かない。画像は相対パスで参照すると HTML に埋め込まれる。

## 組み立てる

このスキルのディレクトリにある `scripts/build.ts` を Node で実行する。デッキはスクラッチパッドに置く。Artifact は作業ディレクトリかスクラッチパッドの下のファイルしか公開できない。

```sh
node <スキルのディレクトリ>/scripts/build.ts <デッキのディレクトリ> <出力先> --pdf
```

- 出力の JSON の `file_path` を Artifact の publish に渡す。`script` は全スライドのスピーカーノートを順につないだ読み上げ原稿である。直すときは同じ出力先にもう一度ビルドし、同じ `file_path` で publish する。`file_path` が変わると別の URL になる。
- `--pdf` を付けると、1 枚を 1 ページにした `slides.pdf` も書き出す。Artifact の中では印刷ができないので、PDF はこのファイルを添付して渡す。持ち主に渡すときは、Artifact のリンク、PDF、読み上げ原稿の 3 つを渡す。
- 渡す前に `scripts/preview.ts <デッキのディレクトリ> <png>` で全スライドを並べた画像を作り、その画像を見て、はみ出し、重なり、不自然な折り返しを探して直す。ビルドが通っても描画は確かめられていない。
