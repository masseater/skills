# テックスタックと、自作の境界線をどこに引くか

ここでは、masseaterのツール群全体を「masseaterエコシステム」、すなわち完成形の状態と、自前で構築したものと借用したものの境界線として説明する。

完成形とは、物事が向かう先のことだ。モノレポへの集約やルート設定ファイルの削除といった移行は、要請があった際に実施される。それまでは、各リポジトリの現行ルールに従うこと。

## 完成形の状態

### 「これが欲しい」と言うだけで構築されたもの

- ユーザーが「これが欲しい」と言えば、ユーザーの手作業なしに構築され、動作する。権限付与などの一部の手作業は許容される。
- 対象は、VSTなどの音楽プラグイン、ゲーム、ゲームのMod、Discord、wiki、意思決定モデルの研究、およびUnityやBlenderにおける3Dである。
- OSを構築しない
- 最終的には、UnityやBlenderの代替ツールを自前で構築しても構わない。その規模での構築は許容される。
- 決めかねていることは、必要になった時に構築する。

### 決定事項

- 採用する言語はTypeScriptとRust。C#は使用しない。ただし、Unity内部で必要な場合に限り、クローズド例外として使用する。
- Pythonは例外なく使用しない。コード、スクリプト、CI、検証、依存関係のどこにも記述せず、Blender内部にも記述しない。ルールはリポジトリの規約にある。
- 音楽プラグインの形式はVST3に基づいている。Logic ProはAUしか読み込まないため、AUを同梱するかどうかは未定である。
- 決済にはStripeのみを使用する。現時点ではライセンスサーバーを構築しない。
- 配布対象はnpmとcrates.ioのみとする。その他が必要になった際に追加する。
- 扱う3Dデータ形式はFBX、`.blend`、glTFである。その他が必要になった際に追加する。
- PC向けのものは、Windows、macOS、Linuxで動作する。必要になった際に常駐プロセスを構築する。
- Claudeは、claude.aiサービスの品質が良いため採用している。モデルは用途に応じて選択し、Claude以外のモデルも使用する。
- UIはReactとTanStack Startで構築する。
- 現在のD1、better-auth、drizzle-ormが、データベース、認証、ORMの標準となっている。
- テストはTypeScriptではVitestとPlaywright、Rustでは`cargo test`を使用する。
- ビジュアルチューニングに関するルールはまだない。
- 計測データはCloudflareで管理している。
- ドメインとDNSはCloudflareで管理している。Cloudflareからは取得できない`.jp`ドメインは、必要に応じて検討する。
- 構築したもののユーザーからのリクエストは基本的に受け付けない。受け付けるかどうかはケースバイケースで判断する。

### 個人利用限定、ベンダーロックインを歓迎。

- 汎用は求めない。自身のユースケースに特化し、他の環境向けのブランチや互換性は持たない。
- Cloudflare、Claude、Vite+、GitHubへの依存を前提とする。SaaSへのロックインでも構わない。
- GitHubは公開リポジトリ向けに無料のActionsを提供しており、Claudeにはクラウド実行環境が付属している。この安さを活かす。

### 1つの公開モノレポに集約する。

- ほぼすべてのリポジトリを1つの公開モノレポに集約する。
- mirucordとkonomiはセルフホスト用なので、別々のリポジトリに留める。
- 持ち主の私的な内容を置くリポジトリは非公開に保つ決まりがあるため、公開モノレポには入れない。
- ワークスペースをアプリ、ライブラリ、ツール、インフラに分ける。VSTのように配布されるものもアプリに入れる。

### 設定の唯一の信頼できる情報源はvite.config.tsである。

- 各リポジトリの設定における唯一の信頼できる情報源を、単一のvite.config.tsに集約する。
- 設定ファイルをルートに置かない。そこに`.gitignore`も置かず、vite.config.tsから`.git/info/exclude`を生成する。`.git/info/`はコミットされないため、Vite+が`core.hooksPath`を設定するのと同様に、ルートを空にできる。

### すべてを測定する

- 各コミットの前後すべてを測定する
- 測定した数値をAI自身が確認でき、後で参照して次の判断に活用できる場所に配置する。

## 構築と借用の境界

### 借用するもの：言語仕様に準拠したコア、および適切に設計されたAPI

- 言語仕様に準拠したコアを借用する。oxcのcrates、tsgo、rustc、rust-analyzer、`cargo metadata`がこれに該当する。
- 他者が適切に設計したAPIを借用する。CloudflareやClaudeのAPI、およびVite Taskのキャッシュとリモートキャッシュがこれに該当する。

コアは仕様が固定されており、不満を招く可能性は低い。再構築しても何も得られず、メンテナンスが増えるだけである。

### 構築するもの：開発者が触れるサーフェス、およびそれらを繋ぐメカニズム

- TypeScriptとRustをシームレスに扱うモノレポ管理ツール
- Vite+の拡張機能：タスクグラフにcratesを配置するCargoプロバイダー、OTLPやWorkers Logsに実行をエクスポートするコンポーネント、および`.git/info/exclude`の生成がこれに該当する。
- リントとフォーマットのサーフェス。コアにはoxcを借用し、ルールや設定のエントリポイントを構築する。
- テストのサーフェス。各言語のテストフレームワークを、単一のエントリポイントから実行可能にする。

構築するものは自社開発であると想定してよい。それ以外のすべてについては、リポジトリの慣習に従った手段を選択し、自前で行わないこと。

これらを構築する理由は、多くの人が影響を受けるため、OSSのアップデートフローが存在するからだ。AIを使って自前で構築するのであれば、そうした手順を省き、問題が発生した際にすぐに修正できる。不満が生じるのは日常的に触れるサーフェスや継ぎ目であるため、自前で管理するものだけに留めておくこと。

### 他に方法がない場合のみ：借用したものを修正する。

- 借用したものをフォークやパッチで修正するのは、拡張ポイントがなく、上流での修正の見込みがない場合に限る。Vite Taskのグラフは`package.json`をノードにするだけで拡張ポイントを持たないため、フォークでグラフのエントリポイントのみを追加する場合がこれに該当する。
- 修正範囲は欠落している部分のみに限定すること。フォークは必ずしも上流との互換性を保つ必要はなく、必要な変更がある場合にのみ選択的に取り入れる。

### 構築すべきではないもの

- OS
- 独自のプログラミング言語

## 議論の流れ

これは2026-11-07のプロジェクトチャットでの議論である。

1. ユーザーは、他者のOSSアップデートフローに縛られることなく、すべてを自前で構築し、問題が発生した際にすぐに修正したいとしている。最も必要なのは、TypeScriptとRustをシームレスに扱うモノレポ管理ツールであり、設定の唯一の信頼できる情報源をvite.config.tsとし、ルート設定ファイルや`.gitignore`すら不要とするものだ。目標は、AIがすべての計測値を自力で調べられる場所を作ることである。
2. Vite+ 1.5.0 が調査された。Vite Taskのキャッシュはプロセスの読み書きを記録するため、言語を問わず動作し、`cargo` も適用可能である。不足しているのはグラフと計測値であり、`package.json`のみがノードになり得、タスク設定は未知のキーを拒否し、拡張ポイントも存在しない。2026年第4四半期の計画 [vite-plus#3277](https://github.com/voidzero-dev/vite-plus/issues/3277) では、JS以外のワークスペースも設けられていない。結論として、ゼロから構築するよりも、Vite Taskをフォークしてグラフのエントリポイントのみを追加するのが最低限である。[moon v2](https://moonrepo.dev/blog/moon-v2.0) はRustとTSを同一のグラフに配置できるが、設定がプロジェクトごとに分割されているため、採用されなかった。
3. ユーザーはベンダーロックインを歓迎し、汎用的な利用ではなく独自のユースケースに特化することを選択した。これにより、フォークはもはや上流との互換性を維持する必要がなくなり、リモートキャッシュが自前のCloudflare上に存在し、計測値がWorkers Logsに送信されるという前提で構築できる。
4. すべてを自前で構築する事例が調査された。成功した事例では、自作する範囲をメイン業務の中核に絞り込んだ。Jonathan Blowは言語を構築し、ゲームをリリースするために10年を費やした。Andreas KlingはLadybirdでSerenityOSの「すべてを自前で」という方針を捨て、グラフィックスとオーディオをライブラリに任せた。破綻した事例では、ツールの構築自体が目的となったか、あるいは本人しか運用し続けられない状態で停滞した。TempleOSやHandmade Heroがこれに該当する。AI時代の事例では、Mario ZechnerがClaude Codeの変更に振り回されないよう、独自のミニマルエージェントであるpiを構築し、Armin Ronacherは[piを修正するためにpiを実行している](https://lucumr.pocoo.org/2026/5/24/pi-oss/)。一方で、Ronacherは[構築があまりに簡単になりすぎて、ブラッシュアップが追いついていない](https://lucumr.pocoo.org/2026/1/18/agent-psychosis/)と記しており、[Personal software factories are a waste of time](https://www.peterp.me/articles/personal-software-factories-are-a-waste-of-time/)と、構築するものが何もない状態でファクトリーを作り続けるという罠を指摘している。
5. 事例に基づき、境界が設定された。コアを借り、開発者が触れる表面と、それらをつなぐ仕組みのみを構築する。言語の構築はスコープ外とした。
6. ユーザーはロックインをSaaSにも拡張した。GitHubが公開リポジトリ向けに無料のActionsを提供し、Claudeがクラウド環境を備えているため、どちらもコストが低すぎるという理屈からだ。この前提で構築されたツール群全体は、「masseaterエコシステム」と呼ばれるようになった。
7. スコープが抽出された。C#とPythonは嫌われているため、UnityとBlenderの内部でのみ例外とされ、将来的にUnityやBlenderに取って代わる規模での構築が認められた。VST3がmacOSで問題になるかという問いに対し、VST3はmacOSでも動作するが、Logic ProはAUしか読み込まないという回答が得られた。Rustの[nih-plug](https://github.com/robbert-vdh/nih-plug)はVST3とCLAPを出力でき、AUには別途ラッパーが必要だ。支払いはStripeのみ、配布はnpmとcrates.ioのみ、データ形式はFBX、`.blend`、glTF、OSはWindows、macOS、Linuxとし、それぞれ不足した際に拡張することとした。不要になったものは自前で構築することとした。
8. 次に、使いやすく手間がかからないReactとTanStack StartをUI用に維持し、計測データ、ドメイン、DNSをCloudflareに移行し、基本的にはユーザーからのリクエストを受け付けないこととした。現在のデータベース、認証、ORMが標準となり、テストについては、言語ごとに異なるフレームワークを使うのは煩雑なため、ユーザーは単一のエントリーポイントを望んでいた。ビジュアルチューニングにはまだルールがなく、最終的には自前で構築することになりそうだった。
9. 2026-11-10にユーザーがPythonを完全に禁止した。コード、スクリプト、CI、検証、依存関係のどこにも記載せず、Blender内部の例外も削除された。Unity内部のみのC#用例外は残っている。
