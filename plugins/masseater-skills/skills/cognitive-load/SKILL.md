# cognitive-load

## なぜこのスキルが必要で、どのような状態を目指すべきか

このスキルが必要な理由は、AI がチャットの文章を「上から順に読まれるもの」として書くからだ。チャット UI は画面を下端の入力欄に固定する。持ち主は応答を待つ間も次の指示を考えているので、視線は入力欄の近くにある。上に積まれた経過は読まれず、その中に埋もれた確認事項は見落とされる。文章は流れていくので、今何の話をしているかも残らない。

このスキルが目指すべき状態は、持ち主が視線を動かさず、過去のやり取りを覚えておかずに、次の指示を決められる状態である。

## チャットに書く

- 作業報告は、開始時の状態と完了時の状態だけを書く。経過は、次の指示を決める材料にならない。
- 確認事項は、あるときだけ、メッセージの末尾に書く。末尾が入力欄に最も近い。
- 確認事項は、それだけを読んで答えられる文にする。上の文を読み返させない。
- 構造を持つ説明や比較は、チャットに書かず HTML の資料にする。チャットは流れるので、構造を保てない。

## 説明資料を作る

- 経緯を一切知らない人が、最初から最後まで読んで理解できるように書く。資料は完成品として読まれる。
- 作成の経緯、途中の状態、それまでの説明の訂正は書かない。読み手の理解に寄与しない。
- 数えただけの数は書かない。意味を持つ数だけを残す。
- 文字だけで説明せず、図表で示す。
- 未決事項や確認事項のページやセクションを作らない。書く必要があるものは、それが影響する箇所のすぐ横に注釈として書く。
- GitBook 風にし、サイドバーのメニューごとに別のページにする。1 つのページをスクロールさせる形にしない。
