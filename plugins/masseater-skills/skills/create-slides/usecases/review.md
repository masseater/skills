# 報告前の確認

デッキの作成が終わったら、オーナーに渡す前に以下の順序で確認すること。ルール自体はSKILL.mdにあり、このファイルにはそれに従っていることを確認する手順のみが記載されている。ライターの頭の中では確認せず、抽出したリストやキャプチャした画像を見て確認すること。

## 構成

1. 完成した各スライドの見出しを並べ、承認済みのアウトラインと1行ずつ照合する。アウトラインに含まれていないスライドと、アウトラインに含まれているが作成されていないスライドを探す。
2. 各スライドについて、聴衆が直前に抱いている疑問を書き出し、そのスライドでそれが解消されるかを確認する。疑問が解消されないスライドは内容の再提示であるため、削除するか元のスライドに差し替える。
3. スライドに2つのトピックがある場合は、分割する。
4. 比較スライドを探し、もう一方の側に一致するスライドがあるかを確認する。
5. 最後のスライドの見出しが「Summary」という一単語になっていないか、また資料をまとめただけのスライドや、「In a word」のスライドがないかを確認する。
6. 承認済みのアウトラインやオーナーの指示のどこにも根拠がない文章やスライドを探す。それらを削除するか、レポート内で追加するかどうかを確認する。

## テキスト

1. すべての見出しを抽出し、各見出しがスライドの図自体を指すフレーズなのか、あるいは図が次に示す内容へと導く導入部なのかを確認する。一文だけの主張、一文だけの事実、「このデッキの……」といったトピック名や装飾が混ざっている場合は、修正する。
2. スライド上のすべてのテキストを抽出し、話し言葉の語尾（「〜だ」「〜なんです」「〜しよう」）、聴衆への直接的な呼びかけ、および定型的な結びのフレーズを探す。
3. フェードイン文を一つずつ削除し、それらがなくても内容が通じるスライドからは削除する。
4. すべての用語を抽出し、同じ意味の単語が2つあるか、抽象的な言い換え（「配布元」など）を実際の名称（「npm」など）にできるか、また略語の初出箇所に正式名称があるかを確認する。聴衆がエンジニアでない場合は、ソースコードやファイル名が表示されていないかも確認する。
5. リポジトリに名詞の語尾文などをチェックするtextlintのルールやフックがある場合は、スライドのテキストとスピーカースクリプトでそれらを実行する。

## 図表・グラフ

1. 図中の各矢印を、どのような条件下で誰が何をどちら側に渡すのかという文章として読み返し、調査した事実と照らし合わせる。また、選択できないものが、選択できそうな見た目になっていないかを確認する。
2. グラフにチェックマークや重要箇所の値、ソースデータの期間、および測定方法の違いに関する注記があるかを確認する。

## 根拠と鮮度

1. デッキに登場するすべてのモデル名とベンチマークを抽出し、それらが最新であるか、また数値がいつ測定されたものであるかを当日の公式発表と照らし合わせて確認する。
2. 評価や重み付けが付与されたスライドに、同一スライド内に根拠となる数値やソースへのリンクがあるかを確認する。

## レンダリング

1. 構築したHTMLのすべてのスライドを、あらゆるクリック状態でキャプチャする。
2. キャプチャした画像を図ごとに切り抜き、少なくとも2倍に拡大する。画像全体が縮小して読み込まれるため、拡大しなければ、点が線からずれるなどのズレは見えない。
3. 拡大した画像において、点が線上にあるか、図のみのスライドで図が中央にあるか、テキストが奇数箇所で折り返しているか、ボックスからはみ出しているものがないかをスライドごとに確認する。
4. モーションについては、録画をコマ送りでレイアウトした画像を使用し、始点と到達点の間で点やラベルが途切れていないかを確認する。
5. 最後に、各スライドが伝えたい内容を、図と見出しだけで理解できるかを読み直す。

## 引き継ぐもの

PDF、HTML、スピーカースクリプトのすべてがレポートに添付されているかを確認する。
