# 公開済みパッケージ

npm に公開したパッケージは、持ち主の管理外のリポジトリや、アップグレードの日が違う持ち主の他のリポジトリにインストールされて動く。公開は、そこで動くという約束である。もとのリポジトリのレイアウト、ファイル、名前、アカウントのおかげでしか動かないパッケージは、そのリポジトリで通っていても、この約束を破っている。

## レビューで問うこと

パッケージを、このリポジトリではない別のリポジトリにインストールしたつもりで見る。次のどれかに当たれば却下する。

- 自分の外へ手を伸ばしている。自分のディレクトリの外のファイルをインポートする、相対パスやカレントディレクトリでリポジトリのファイルを読む、自分の場所から上へたどってリポジトリのルートを探す、`libs/` や `apps/`、ワークスペースのファイルといったレイアウトを前提にする。必要なものはすべて、自分のファイル、宣言した依存関係、呼び出し側が渡すものから得る。
- このリポジトリの名前を持っている。持ち主やリポジトリの名前、ドメイン、アカウント ID、非公開リポジトリの名前が、呼び出し側が渡すべき場所に定数として書かれている。1 つのリポジトリにしか合わない値はオプションにし、すべての利用者に合うときだけ既定値を持たせる。
- 持ち主のインフラに依存している。読み込みや実行に、持ち主の MCP サーバー、Workers、アカウント、認証情報のブローカー、非公開のパッケージのどれかが要る。サービスを呼ぶパッケージは、利用者自身の認証情報を設定から読む。
- リポジトリがたまたま巻き上げているものに頼っている。宣言していないパッケージや devDependencies にしかないパッケージをインポートする、非公開の、または npm にない `workspace:` パッケージに依存する。
- 内部をさらしている。`exports` に入口が足りない、型が同梱されていない、呼び出し側が深いパスをインポートしなければならない。
- リポジトリの外で確かめられていない。テストがない、またはタールボールからクリーンな利用側へインストールしたことがない。
- 初めて見る人に分からない。README が英語でない、何であるか・どう使い始めるか・どこで公開されているかが書かれていない、`description` に何をするかと使う場面が書かれていない。`vp pm search maintainer:r_masseater` が表示するのは `description` だけである。
- 誰も必要としていない。このリポジトリでしか使わないパッケージは非公開のままにする。公開するのは、公開が要るものだけである。

## 対応範囲

- パッケージが必要とするすべてのツールチェーンについて、対応する範囲を宣言すること。正確なバージョンは書かない。Node.js は `engines.node`、Rust のクレートは `rust-version`、Vite+ は `peerDependencies` の範囲で宣言する。各範囲は、そのツールの最新のメジャーとマイナーのリリースにまたがる。
- 宣言した範囲が正しいと示せるよう、各範囲の両端、つまり対応する最も古いリリースと最新のリリースの両方でテストする。
- リポジトリ間でバージョンを同期させる仕組みを作らない。各リポジトリが自分で宣言する。

## 境界

- パッケージの境界は凝集で引く。目的が同じで、一緒に使われ、一緒にバージョンを上げるものを 1 つにする。公開するパッケージを減らすためだけに無関係なコードをまとめず、別々に使われるコードは分ける。
- 一部の利用者にしか要らない重い依存関係は、dependencies ではなく、省略可能なピア依存関係（`peerDependenciesMeta` の `optional: true`）にする。

## msch が検査するもの

- `msch-publish compat` は、パッケージと、それが依存するワークスペースをビルドしてパックし、タールボールをクリーンな利用側へインストールして、公開しているすべてのエクスポートをインポートし、公開しているすべての bin を起動する。宣言した中で最も低い Node.js とピアのマイナー、および最新で行う。読み込めないモジュール、足りないモジュール、エクスポートされていないサブパスで失敗する。`verify` のワークフローで動き、公開の前にもう一度動く。
- `msch-publish` は、`workspace:` の依存関係が現在の版で npm にないパッケージを断る。
- `published-readme` は英語の README を、`published-tests` はテストを、`published-skills` はエージェント向けのスキルを、`package-scope` は `@r_masseater` のスコープだけを、`pack-publint` は厳格な publint を、`install-size` はインストールサイズの上限と省略可能なピアへの案内を、`node-version` は `engines.node` を、それぞれ求める。

モジュールが実行中に何をするかは、msch には決められない。リポジトリのファイルを読むこと、このリポジトリの名前を持つ定数、持ち主のインフラが要ること、境界の凝集がこれに当たる。`rust-version` の両端を試すものも無い。これらはレビューで見つけること。
