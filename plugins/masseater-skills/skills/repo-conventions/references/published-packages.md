# 公開済みパッケージ

npm に公開されたパッケージは、所有者が管理していないツールチェーンと共にインストールされ、所有者自身のリポジトリは日によって異なるタイミングでアップグレードされる。ある特定の環境に適合するルールが、他の環境では通用しなくなる。

- パッケージが必要とするすべてのツールチェーンのサポート範囲を宣言すること。正確なバージョンは書かないこと。Node.jsの場合は `engines.node`、Rustクレートの場合は `rust-version`、Vite+の場合は `peerDependencies` の範囲とする。各範囲は、そのツールの最新のメジャーおよびマイナーリリースにわたるものとする。
- ecosystems の CI では、サポートされている最古のリリースと最新のリリースの両方をテストし、宣言された範囲が検証されるようにする。
- リポジトリ間でバージョンを同期させる仕組みを構築してはならない。各リポジトリは個別に宣言を行う。
- パッケージの境界は凝集で引く。目的が同じで、一緒に使われ、一緒にバージョンを上げるものを 1 つにする。公開するパッケージを減らすためだけに無関係なコードをまとめず、別々に使われるコードは分ける。
- 一部のユーザーにしか要らない重い依存関係は、dependencies ではなく、省略可能なピア依存関係（`peerDependenciesMeta` の `optional: true`）にする。

msch はすでに、公開パッケージに `engines.node` を求め（`node-version`）、インストールサイズが上限を超えたときに省略可能なピア依存関係を案内する（`install-size`）。パッケージの境界は凝集の判断であり、チェックでは決められない。Rust と Vite+ の範囲、および CI の両端のテストを確かめるチェックは、まだ無い。
