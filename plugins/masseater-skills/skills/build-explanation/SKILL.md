# build-explanation

解説が伝わるかどうかは、内容の正しさよりも、読み手の頭の中で理解が組み立てられる順序になっているかによって決まる。このスキルでは、新しいことをどう理解するかに応じて、話の順序を決定する手順を提示する。スライドの場合、このスキルは構成とスピーカースクリプトで活用される。見た目や言い回しのルールはここでは扱わず、文章はyomiyasuでブラッシュアップされる。

## 解説をどう理解するか

各ステップは、以下の7つの特性に基づいている。出典は末尾の参考文献に記載されている。

| 特性 | 解説にとっての意味 |
| --- | --- |
| 新しい情報は、すでに分かっていることと結びついて初めて理解できる。 | 読み手が知っていることから始める。内容を把握せずに読んだテキストは、一文ずつは理解できるが、全体としては理解できず、記憶にも残らない。 |
| 一度に頭の中に保持できるのは、約4つの要素である。 | 用途が不明な箇所を先に並べると、読み手は意味のない要素を抱えたまま読み進めなければならなくなる。 |
| 人は疑問を持ったときに回答を受け止める。 | 回答の前に、読み手がその答えを知りたいと思わせるような問いを立てる。特に大人は、なぜそれを知る必要があるのかが分かるまで、学ぼうとしない。 |
| 具体的なものから抽象的なものへと進めることで、理解しやすくなる。 | まずは馴染みのある例や実物を提示し、そこから一般化された言葉や仕組みへと移行する。 |
| 物語形式のテキストは、説明的なテキストよりも理解しやすく、記憶に残りやすい。 | 項目を列挙するのではなく、質問と回答を紐づけて起点から進む、一つの連続した物語にする。 |
| 読み手が抱いている誤解は、正しい解説を加えるだけでは消えない。 | よくある誤解を挙げ、それを否定し、なぜそれが間違っているのかを示す。 |
| 何が理解しやすいかは、読み手の知識次第である。 | 順序を決める前に、想定読者を定める。知っている人には通用する省略が、知らない人には飛躍となる。 |

## 手順

### 1. 核心となる文を決める

読み手が読み終えたときに持ち帰ってほしい理解を、主語と述語を持つ一つの文として書き出す。核心を決めずに用語や事実を並べると、たとえ各解説が正しくても、読み手は何について書かれていたのか分からなくなってしまう。

### 2. 読み手の起点を決める

想定読者がすでに知っており、この話につながる具体的な事柄を一つ選び、書き出す。起点としては概念よりも、体験や実在するものの方が適している。例えば、LLMの仕組みについて、誰もが見たことのある「ChatGPTに質問すると、少しずつテキストが返ってくる」という場面が起点となる。起点を言葉で述べるだけで終わらせず、実際に動作している様子を先に見せる。ChatGPT内部の仕組みについて話すなら、仕組みの話の前に、質問を入力して答えが少しずつ出てくる画面を置いておく。読み手は見た現象を手がかりとし、後に出てくる仕組みと結びつける。起点を決められないのは、想定読者が知っている範囲を間違えているということだ。まず想定読者を書き直し、それからこのステップに戻る。

### 3. 読み手に疑問を持たせる

起点で現象を示した後、答えを言う前に、その現象について「なぜそうなるのか」が読み手の頭に浮かぶような疑問を投げかけ、示す。疑問を伴わない説明は、読み手にとっては答えが並んだ情報に過ぎない。ゆっくり解説風の解説動画はこの形式で進める。聞き手役がまず疑問を口にし、解説者がそれに答える。解説者が先に答えについて話し始めることはない。読み手が当然だと思っていたが、指摘されると不思議に思う点から疑問を持たせる。ChatGPTにとって、「なぜ答えが一語ずつ出てくるのか」や「教えるべきではないことにどう答えるのか」は疑問になる。疑問を書き手の頭の中だけで使わない。スライドでは、本文や図などの文字、あるいは話し手の台本の直接の呼びかけとして、読み手に見える形で出す。

### 4. 疑問の連鎖を書く

起点から核心文まで、「読み手が次に抱く疑問」と「その答え」をペアにして1列に並べる。各ステップの答えが次のステップの疑問を生むように結びつける。疑問に答えないステップは読み手にとって唐突なので、削除するか、疑問が生じるべき箇所に移動させる。スライドの場合、この列がそのままスライドの順序になる。各スライドの冒頭では、前のスライドから来る疑問を取り上げる。

LLMの仕組みを説明する例を挙げる。

| 読み手の疑問 | 答え |
| --- | --- |
| （起点）ChatGPTに疑問を投げかけるとテキストが返ってくる | |
| 内部で何が起きているのか？ | 次の単語の確率を計算し、単語を一つずつ足してテキストにする |
| その確率はどうやって計算するのか？ | 膨大な数の数値を用いて、乗算と加算で計算する。これらの数値をパラメータと呼ぶ。 |
| 誰がその数値を決めたのか？ | 人間ではなく、膨大なテキストと答えを繰り返し照合して修正した。これは学習と呼ばれる。 |

この例では、「内部の値」という言葉が出た直後に初めて「パラメータ」という名称が与えられている。冒頭で「パラメータとは何か？」と切り出すと、読み手はなぜそれを耳にするのかが分からない。

### 5. 疑問への答えとして用語を導入する

トークの中で言及されている用語を説明する。冒頭で「……とは何か？」というスライドや段落をまとめない。まず言及されている対象の機能や役割を示し、その後に名称を述べるという順序にする。名称が先になると、読み手は内容を知らないラベルを握らざるを得ない。説明の中では、単語が何を指す前に、なぜそれが必要なのか、何が問題になるのかを記述する。定義よりも必要性が読み手をつまずかせる。例外は、全体の流れを一度示した後に詳細に入る場合だ。その場合は、詳細で使用した箇所の名称を、直前に簡潔に併記してもよい。全体の流れを示す前に用語集を添える場合は、この扱いには当たらない。

### 6. 部分に入る前に全体を示す

仕組みや動作原理を説明する際は、部分から積み上げて説明してはいけない。まず「そもそもどういう仕組みなのか見てみよう」というように、全体の流れを一度示し、その後に各部分を詳しく見る。部分に入る際は、その都度、全体のどこに位置づけられるかを示す。読み手は全体の流れを地図として持ち、そこに部分を配置することで理解する。

### 7. 具体的なものから抽象的なものへ

具体的な例や実物を先に示し、その後に一般化された言葉や仕組みに言い換える。抽象的な定義から始めて、後から例を付け加えてはいけない。仕組みを説明する際、具体的なものとは、その仕組みが働いた結果として読み手に見える現象のことだ。仕組みの図の前に、画面や出力、動きといった現象そのものを示す。比喩を用いる場合は、どこが元の話に該当し、どこが異なっているかを明確に述べる。対応関係を示さない比喩は、読み手に誤った推論を導く可能性がある。

### 8. 読み手がどこでつまずきやすいかを想定する

アウトラインを作ったら、想定読者になったつもりで上から読み、各ステップで生じる疑問を書き出す。必ず以下の3つを確認すること。

- なぜ必要なのか
- なぜ他の方法ではうまくいかないのか？
- 読み手にとって何が変わるのか？

書き出した疑問のうち、核心となる文を理解するために必要なものを本文で答える。疑問が生じたステップの直後にそれぞれ答える。想定読者が抱きそうな誤解（「AIが答えを検索する」など）がある場合は、その誤解を列挙し、なぜそれが間違っているのかを根拠とともに示す。正しい説明だけを書いていると、読み手は自分の誤解と結びつけずに読み飛ばしてしまう。

### 9. 新しい要素を一つずつ導入する

新しい概念は、1スライドまたは1段落につき1つだけ導入する。新しい概念を導入する際は、それを理解するために必要な前提条件が先に現れているかを確認する。そうでなければ、前提条件を先に導入するか、新しい概念を後から移す。

### 10. 主張に読み手向けの根拠と意味を添える

説得したい主張には、その根拠と読み手にとっての意味を添える。読み手が「この話は自分に関わるものだ」と感じれば感じるほど、根拠の質を精査するようになる。強い根拠は説得力を高めるが、弱い根拠や飾り言葉は逆効果になる。主張を強く見せるために、調べた事実よりも強い表現を用いてはならない。

## 確認

アウトラインとスクリプトが完成したら、想定読者になったつもりで上から読み、以下を確認する。見つけた箇所は修正してから提出する。

| 確認事項 | 見つけた際の修正方法 |
| --- | --- |
| 最初のステップは、読み手が知っている内容から始めるか？ | 出発点を改めて決め、そこから疑問の連鎖を書き直す |
| 仕組みについて話す前に、実際に動作することが示されているか？ | 仕組みのステップの前に、実際の画面や動きを示すステップを追加する |
| 各ステップの冒頭で、読み手はなぜ今これを読んでいるのかが分かるか？ | 前のステップの回答から生じた疑問を、そのステップの冒頭に配置する |
| 説明なしに出現する単語や、使用されている箇所から離れた場所で説明されている単語はないか？ | 説明を、その単語が最初に登場するステップに移動させる |
| 疑問の連鎖がどこかで途切れていないか？ | 欠けている質問と回答を追加するか、ステップの順序を入れ替える |
| 想定読者の誤解に触れることなく、話が進んでいるか？ | 誤解を指摘し、否定するステップを追加する |
| すべてのステップが核心となる文に向かっているか？ | 核心に向かっていないステップを削除する |
