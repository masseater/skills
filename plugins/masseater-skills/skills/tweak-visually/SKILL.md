# tweak-visually

見た目の調整は、言葉で指示して AI が値を推測する往復にしない。持ち主が要素を選んで動かし、確定した値だけを受け取ってソースに反映する。

## なぜこのスキルが必要で、どのような状態を目指すべきか

このスキルが必要な理由は、見た目の値が言葉では決まらないからである。「もう少し丸く」と言われた AI は値を推測して CSS を書き、持ち主は画面で見て、また言葉で直す。この往復は、毎回の推測が外れるたびに増え、持ち主は手で CSS を書く代わりに、CSS の値を言葉に直す作業を負う。

このスキルが目指す状態は、見た目の値を持ち主が画面上で直接決め、AI がそれを推測せず、決まった値だけをコードに残すことである。

## ルール

- 対象は Vite の React アプリである。それ以外では使わず、通常の手順で直す。made-refine がこの構成で確かめてあるためである。
- 持ち主が触る画面は、claude.ai のアーティファクトとして公開する。クラウドで起動した開発サーバーには、持ち主の PC から届かないためである。
- 編集用の変更（依存、`<DirectEdit />`、ビルド設定）は作業用のブランチだけに入れる。ソースのブランチに残すと、編集画面が本番に混ざるためである。
- 編集中の画面には何も書き込まない。動かすのは持ち主で、Claude は確定した値が届くのを待つ。値を推測して先回りすると、持ち主が決めた値を上書きするためである。
- 受け取った差分は、そのリポジトリが既に使っているスタイルの書き方（Tailwind、CSS Modules、トークンなど）に直して、ソースのブランチに反映する。made-refine の出力そのものをインラインスタイルで貼らない。
- アーティファクトは外部への通信ができない。API を呼ぶ画面は、固定のデータで描画する。

## ユースケース
