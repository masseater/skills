# 台本を作劇で書く

台本は、持ち主と3つのゲートで決めてから描く。各ゲートは1つのことを決め、決めたことは後のゲートで変えない（制作の承認ゲート。[Pixflow](https://pixflow.net/blog/?p=93333)、[Boords](https://boords.com/blog/the-seven-steps-of-animation-production)）。後で変えたくなったら、それを決めたゲートに戻ってやり直す。持ち主に見せる物は決まった形にし、持ち主は印を付けるか一言返すだけで済むようにする。

| ゲート | 持ち主に見せる物 | 決まること |
| --- | --- | --- |
| 1. ネタ表 | 主張の表 | 何を主張し、どれを主役にするか |
| 2. 台本 | Story Spineの8文と出典 | ナレーション、主張の言い方、数字 |
| 3. ボードマティック | 各拍の静止画1枚をナレーションの音声に合わせて流したもの | 各拍の画面と間 |

ゲート3の後は、SKILL.mdの品質チェックとサブエージェントの評価を通して、完成版を見せる。

## 1. ネタ表を作る

1. 対象を一次情報（公式サイト、リリースノート、ベンチマーク）で調べ、見る人の得になる事実を集める。版と日付を書く日に確かめる。
2. 事実を主張にまとめる。主張は見る人が得るもの（速い、容量が増えない、更新が速く便利機能が次々増える）にし、機能や数字はその証拠として下に付ける。同じ主張を支える機能が2つ以上あるなら、機能ごとの行にせず1つの主張にまとめる。見る人は個々の機能の中身ではなく、それが言える理由を受け取る。
3. 次の形の表を持ち主に見せ、主張ごとに「主役」「触れる」「外す」を付けてもらう。AIの推しは仮の印として入れておく。

| 主張 | 証拠（画面に並べるだけ） | 出典 | 印 |
| --- | --- | --- | --- |
| インストールが速い | npm 43.1秒、pnpm 4.0秒 | pnpm.io/benchmarks | 主役 |
| 容量が増えない | パッケージはPCに1つ | pnpm.io/motivation | 触れる |
| 更新が速く便利機能が次々増える | 11.0 `minimumReleaseAge`、12.4 Rust、12.11 スキル | 各版のリリースノート | 触れる |
| 古いツールで動かないことがある | 設定1行（`nodeLinker: hoisted`）で直る | pnpm.io/settings | 触れる |

- 主役は、見る人が「すごい」と感じる主張から選ぶ。数は決めず、尺に合わせて削らない。ショートで見る人に残るのは詳しさではなく驚きなので、驚きのない主張は「外す」にする。
- 持ち主が行の粒度を直した（機能の行を主張にまとめた、など）ら、その直し方を手順2の基準として次から使う。

## 2. 台本を書く

台本は、[`cast`](../references/cast.md)の2人の寸劇として[Story Spine](https://www.npr.org/transcripts/nx-s1-5750619)の8文で組む。文の書き出しが決まっているので、埋める中身だけを考えればよい。

1. 次の表の書き出しに続けて、1拍ずつ1文で埋める。主役の主張は「Because of that」の拍に1つずつ入れる。「触れる」の主張は「Until finally」の前の「ほかにも」の拍に全部まとめる。
2. 各拍に、ナレーション、字幕、画面の3つを決める（下の「書くことと読むこと」）。
3. 画面は、その拍の文から見る人が思い浮かべる場面にする。2人が演じる寸劇、図、数字のどれかで、拡大や文字だけの画面にしない。
4. 全台詞を、書いていない別のエージェントに下の「台詞を自然にする」の基準で1行ずつ採点させ、直す。書いた本人は自分の意図で行間を埋めて読むので、唐突さに気付けない。
5. 8文を拍、文、画面、出典の表にして持ち主に見せる。

| 拍 | 役割 | 画面 | pnpmでの例 |
| --- | --- | --- | --- |
| Once upon a time | 誰がどこにいるか | 題名のカード（ツールの分類、名前、何秒で解説するか） | 次世代のパッケージマネージャpnpmを30秒でつむぎが解説 |
| Every day | 見る人が普段やっている場面と、そこにある不満 | つむぎがその作業をして困る寸劇 | `npm install`の秒数が伸び続け、ずんだもんが汗をかいて苦しむ。「npmのインストール遅すぎるのだ」 |
| One day | 乗り換える、試す | その操作 | つむぎ「pnpmに変えてみ？」と`pnpm install`を打つ |
| Because of that | 主役の主張と、その結果 | 前と後を同じ条件で並べた数字、結果を体で表す寸劇 | npm 43.1秒とpnpm 4.0秒の棒にずんだもんが驚き、「爆速っしょ」でつむぎが走り去る |
| Because of that | 2つ目の主役の主張と、その理由 | 仕組みの図 | 2回目は0.4秒。パッケージはPCに1つだけ置くから容量も増えない |
| ほかにも | 前の拍を受ける一言と、「触れる」の主張をまとめた1文 | 証拠の項目が一気に画面を埋める、回数を数え上げる | つむぎ「それだけじゃないよ！」「便利機能も盛りだくさん！」で機能名が次々に叩きつけられ、「しかも3か月で24回もアプデしてるし」で版がv12.0からv12.24まで回る。ずんだもん「最強すぎるのだ！」 |
| Until finally | 試練（つまずき）と、その解決 | 失敗が見え、直って変わる様子 | ずんだもん「さっそく前のプロジェクトもpnpmにしてみるのだ」「…あれ、動かないのだ」でエラー、つむぎ「それ、設定1行で直るよ」で✓に変わる |
| Ever since then | 新しい日常と、見る人が次にやること | 結論と、打てるコマンド | つむぎ「ね、もうnpmには戻れないっしょ？」、ずんだもん「全部のプロジェクト変えるのだ！」と`npx get-pnpm` |

- 不満は台詞で言うだけでなく、見る人が普段いる場面として演じる。言葉だけの不満には共感が生まれない。
- 結果の数字は、同じ条件で測った出典の値どうしを並べる。
- 試練を出したら、同じ拍で解決まで見せる。不安だけ残すと乗り換えをためらわせる。
- 「ほかにも」の拍では、機能の中身を説明しない。主張は「盛りだくさん」「次々増える」ことで、項目の数、出る速さ、回数がその証拠になる。

## 3. ボードマティックで画面と間を決める

1. `script.ts`の`cuts`に拍の順で並べ、`video.tsx`の`draw`に各拍の画面を、動きを付けずに1枚ずつ書く。
2. 各拍の静止画を、その拍のナレーションの長さだけ映し、ナレーションの音声を重ねたMP4を描画する。
3. 持ち主に見せ、拍ごとに直す点をもらう。
4. 決まったら各拍に動きと効果音を付け、完成版を作る。

## 台詞を自然にする

台詞は、見る人が初めて聞いてそのまま分かる会話にする。説明を2人に割り振っただけの台詞は、見る人に台本が透けて聞こえる。

- 各台詞は直前の台詞を受ける（即興のYes, and）。受けない台詞は、話題が飛んだように聞こえる。
- 問題や新しい話題は、前振りを置いてから出す（漫才のフリ、setup/payoff）。前振りなしの「動かないのだ」は、何をして動かないのか見る人に分からない。
- 情報は知らない側（ずんだもん）の問いや行動で引き出し、知っている側（つむぎ）が答える。2人とも知っていることを言い合う説明台詞（As you know, Bob）は不自然になる。
- 話し言葉の文末で終える。「〜から」「〜ので」で切った文や体言止めは書き言葉に聞こえる。同じ文末を2行続けない。
- 1行は18字前後までにし、画面に出ている数字や項目は読み上げない。
- そのキャラが普段使わない語を使わない（[`cast`](../references/cast.md)のペルソナ）。

## 書くことと読むこと

[Mayerのマルチメディア学習の原理](https://www.unh.edu/teaching-learning-resource-hub/sites/default/files/media/2023-06/itow-research-based-principles-for-designing-multimedia-instruction-mayer.pdf)に従う。言葉は絵と一緒なら文字より声で伝える（modality）。声と同じ文を画面に重ねない（redundancy）。ただし、図の該当箇所の横に置く短い要語は例外である。要の語は目立たせる（signaling）。ショートは音を消して見る人が多いので、字幕は声の代わりとして声と同じ文を出す。

情報の種類で、声にするか画面に書くかを決める。

| 情報の種類 | ナレーション（字幕も同じ） | 画面 |
| --- | --- | --- |
| 主張、気持ち、つなぎの言葉 | 言う | 書かない |
| 数字 | 丸めて言う（4秒） | 単位付きで正確に書く（4.0秒） |
| コマンド、設定名、URL、出典 | 言わない | 書く |
| 3つ以上の項目 | 数だけ言う | 項目を書く |
| 関係、仕組み、前と後 | 1文で言う | 図にする |
| 見る人が覚えるか打つもの | 言わない | 書く |

VOICEVOXは漢字の読みをよく間違える（「至れり尽くせり」を「いたれりことごとくせり」、「爆速」を「ばくはや」と読む）。描画の前に全行をVOICEVOXの`audio_query`に通して返る`kana`を読み、違う読みの語は`say`に`{至れり尽くせり|いたれりつくせり}`と書く。字幕には前半の漢字が、読み上げには後半のひらがなが渡る。
