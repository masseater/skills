# weekly-review

## このスキルが存在する理由と目指すべき状態

このスキルが必要な理由は、持ち主が後から「この週は何をしていたっけ」と思い出すとき、数秒しか目を走らせないからである。1 週間の作業は多くのスレッド、プルリクエスト、ページに散らばっていて、AI がまとめると、見たものを出どころ（スレッド、リポジトリ、件数）ごとに並べがちになる。持ち主は週をスレッドやリポジトリで覚えていないので、そうした一覧は一度読まれたきりになり、その週は思い出せなくなる。

このスキルが目指す状態は、プロジェクトの週ごとに記録が 1 つずつあり、その週で何が変わったかが一目で分かり、理由や根拠は持ち主が見たいときに開けることである。

## ルール

- 週は月曜 00:00 から日曜 24:00（JST）とする。タスクが動いたら、直前に終わった週を振り返る。
- その週について次の情報源を読む。この claude.ai プロジェクトでその週に動いたスレッド、持ち主のリポジトリ全体でその週にマージされたプルリクエスト（`gh api -X GET search/issues -f q='is:pr is:merged user:masseater merged:<from>..<to>'`）、その週に公開したブログ記事やページ。情報源に書かれていないことは推測で埋めない。
- 記録は masseater-mcp のポータル経由で watashi の `memory_write` ツールで書く。`project` はこの claude.ai プロジェクトの名前、`name` は `weekly-<月曜の YYYY-MM-DD>`、`description` は見出しの 1 文、`content` は同じ内容を Markdown にしたもの、`view` は部品の木にする。同じ名前で書き直すと記録が置き換わり、前の記録は版として残るので、再実行は上書きでよい。
- `view` はツールのスキーマの説明に沿って組み、次を守る。
  - 先頭に `Headline` を 1 つ置く。その週に何をしたかを 1 文で書く。例：「監査の定期タスクを4つにまとめた週」。
  - 最上位の `Point` は 3 つまでにする。1 つの `Point` は 1 つの成果、つまり何ができるようになったか、何を決めたかを 20〜30 字程度で書く。複数のスレッドの作業が同じ目的に向かっていたら、1 つの成果にまとめる。
  - `Point` の `detail` には、持ち主がクリックしたときに要るもの、つまり理由、変わったこと、プルリクエストやページへの `Links` を入れる。
  - 決めたこと、持ち越し、残りの根拠は、閉じた `Fold` 1 つにまとめる。
  - 件数、スレッドやリポジトリごとの一覧、プロジェクト名、スレッドのタイトルは書かない。日付はポータルが出す。
- 持ち主は日本語を読むので、文言はすべて日本語で書く。
- その週に何も無かったときも、そう書いた見出しで記録を残す。記録が無い週は、タスクが動かなかったことを意味するようにするためである。
- 読めなかった情報源があるときは、残りから記録を書き、読めなかった情報源と理由を `Fold` に入れ、このスレッドへの報告の先頭にも書く。
- 記録を書いたら、`https://portal.masseater.dev/weeks` へのリンクを 1 行で投稿し、このスレッドを解決する。
