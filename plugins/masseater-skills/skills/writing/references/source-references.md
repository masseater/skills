# 参照先は機械が確かめられる記法で書く

リポジトリの名前、パス、関数名を文章の中に書き写すと、リポジトリが改名されたりファイルが移ったりしても、文章は古いまま残る。実際に、msch の置き場所を masseater.dev と書いたスキルが2つあり、人が見つけて直すまで誰も気づかなかった。

参照先をリンクの宛先として書くと、msch が宛先を毎日確かめ、古くなった参照を報告する。

## 記法

Markdown のリンク、リンク定義、自動リンクの宛先に次の形を書く。

| 参照先 | 書き方 | 確かめること |
| --- | --- | --- |
| GitHub のリポジトリ | `[msch](github:masseater/ecosystems)` | リポジトリがあること。改名とアーカイブがないこと |
| リポジトリ内のパス | `[msch](github:masseater/ecosystems/libs/msch)` | 既定ブランチにそのファイルかディレクトリがあること |
| ファイル内の宣言 | `[Config](github:owner/repo/src/config.ts#Config)` | そのファイルがその名前を宣言していること。`Config.validate` のように `.` でつなげる |
| npm のパッケージ | `[effect](npm:effect)` | 公開されていて、最新版が deprecated でないこと |
| npm のパッケージの版 | `[effect](npm:effect@4.0.0)`、`[effect](npm:effect@beta)` | その版か dist-tag があり、deprecated でないこと。範囲（`^4`）は書けない |

- 行番号のアンカー（`#L10`）は、ファイルが変わるとすぐにずれるので書けない。宣言名で指す。
- パスに末尾のスラッシュ、`.`、`..`、空のセグメントは書けない。
- 指す先は既定ブランチの最新である。特定のコミットを指したいときは、通常の `https://github.com/.../blob/<sha>/...` を書く。検査の対象にならない。
- READMEのように、読者が GitHub 上でクリックするリンクは `https://github.com/<owner>/<repo>/blob/<ブランチ>/<パス>` のままでもよい。`<ブランチ>` がコミットでなければ、同じ検査の対象になる。

## 使い分け

- 他のリポジトリのファイルやディレクトリを文章で指すときは、パスをバッククォートで写さず、この記法のリンクにする。
- 別のリポジトリのツールやライブラリの名前を出すときは、リンクにしてリポジトリかパッケージを指す。
- 自分のリポジトリの中のファイルは、相対パスのリンクにする。この記法は使わない。

## 検査

構文の誤りは y8 の `docs/source-reference` 規則が、検査のたびに指摘する。リンク先の実在は `msch-refs` が毎日確かめる。非公開のリポジトリは `GH_TOKEN` か `GITHUB_TOKEN` がないと読めず、実在しないものとして報告される。詳細は `msch-checks` スキルの「Reference links」にある。
