# 開発フローとコードの置き場所

基本はすべてを 1 つの大きなモノレポで開発する。コードを 1 つのリポジトリに置くと、共通部分を見つけて抽象化できる。リポジトリを分けると、似たコードに気づきにくくなる。

## 各リポジトリの役割

- masseater.dev には、masseater が動かしているものがある。個人サイト、アプリ、インフラのスタック、ツール、アプリが共有するライブラリである。アプリは Web サービスに限らず、デスクトップアプリ、音楽プラグイン、ゲームの Mod、Unity のプロジェクトも含む。Cloudflare 上で動き、main からデプロイされる。
- ecosystems には、他の人や他のリポジトリが npm から取り出せるものがある。現状はツールチェーンで、リポジトリの検査（`msch`）、リンターとそのプリセット、`.fumx` のパーサー、それらに必要なライブラリである。すべて `@r_masseater/*` として公開されている。
- 持ち主の私的な内容は、非公開のリポジトリ（リポジトリ ID 1403864815）に置く。
- 独立したリポジトリは、下の分ける条件を満たしたときだけ置く。

## 置き場所

- npm から他の人が使えるものは ecosystems に置く。masseater が動かすものは、Web サービスでもデスクトップアプリでも Web 以外で動くソフトウェアでも、masseater.dev に置く。
- 依存は masseater.dev から ecosystems への向きだけにする。ecosystems は masseater.dev に依存せず、Cloudflare のリソースやデプロイも持たない。ecosystems が masseater.dev にあるものを必要とするときは、それを ecosystems に移す。
- 何かを作る途中で汎用的に使えそうなパッケージが出たら、まず masseater.dev の `libs/` にワークスペースのパッケージとして置く。2 つ目の利用者が現れたとき、または公開する価値がはっきりしたときに、ecosystems に移して公開する。そのあと masseater.dev はワークスペースのコピーから公開版に切り替える。それまでは公開しない。ソースが masseater.dev に残ったまま公開済みのパッケージを置かない。
- masseater.dev と ecosystems の分離が終わるまで、masseater.dev の `libs/` には ecosystems のパッケージのコピーが残っている。正本は ecosystems である。変更は ecosystems に入れ、コピーには入れない。

## 独立したリポジトリに分ける

- 次の両方を満たしたときに分ける。1 つ目は、モノレポに置いておく利点が無いことである。安定していて、共有できるものが残っていない。2 つ目は、モノレポに置いておく負担が実際に効いていることである。Actions のキャッシュ（既定で 1 リポジトリ 10 GB）が埋まる、型付き lint や `msch` でセッションのメモリが跳ね上がる、verify に時間がかかる、変更の影響が広い、独立したリリースや Issue を持てない、などがある。
- 負担が小さいときは、分けずに、まずモノレポの中で減らす。
- フォークできるようにすることは、分ける目的の 1 つになりうる。例は mirucord で、他の人がフォークして自分でホストするためのものである。分ける理由はこれだけではなく、これが主な規則でもない。
- 誤った分け方は、どちらのリポジトリの中からも気づきにくい。日次の監査は、`fallow` でリポジトリをまたいだ類似コードの検査をし、見つかったものは 1 か所にまとめる。

## 必要になったとき

分けるのは、次のいずれかの事実が、いま起きているときだけである。起きていなければ分けない。事実は、示せる形で書く。

- 別のリポジトリに分ける。「独立したリポジトリに分ける」の 2 つの条件を両方満たしたときである。負担は、キャッシュの使用量、メモリ、verify の所要時間など、測った値で示す。
- ecosystems のパッケージとして公開する。masseater.dev 以外のリポジトリが、そのパッケージを npm から使う必要が実際に出たときである。2 つ目の利用者が実在することが条件で、見込みでは足りない。
- 共通のパッケージやライブラリに切り出す。同じ処理が 2 か所以上に実際にあり、`fallow` の類似コード検査が報告したときである。1 か所にしかない処理は切り出さない。

## 例

- 新しい lint ルールやリポジトリの検査は、ecosystems の `msch` に入れる。新しいファイル形式のリンターは、エンジンのパッケージ 1 つとプリセットのパッケージ 1 つとして ecosystems に入れる。
- 新しい Web サービスは、masseater.dev の `apps/` に置き、スタックをその隣に置く。そこから出たトレースの補助は、masseater.dev の `libs/` に置く。別のリポジトリが必要としたとき、ecosystems に移して公開する。
- 新しいデスクトップアプリは、`yogoto` のように `apps/` に置く。複数のデスクトップアプリが共有する殻や計測は `libs/` に置く。
- Web 以外で動くソフトウェアも同じ流れにする。音楽プラグイン（`pod-rattle-plugin`）、ゲームの Mod（`sts2-mods`）、Unity のプロジェクト（`aredoko-unity`）は、それぞれ `apps/` に置く。サーバーやツールと共有するプロトコルは、`sts2-protocol` のように `libs/` に置く。
