# requirements

ユーザー、目的、および想定規模を確認する。これらが決まらなければ、他の領域を満たすための条件も決定できない。[AWS Well-Architected Framework](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html)の手法に従い、負荷と要件に基づいて設計を決定する。

| 確認事項 | 現状の確認方法 | 満たすための条件 |
| --- | --- | --- |
| ユーザーと目的 | READMEとドキュメントを読む | 誰が利用し、何ができるかが記載されている |
| 想定規模 | 規模の説明と本番分析の数値を比較する | 次の段階におけるユーザー数、リクエスト数、データ量を数値で記載し、測定された本番値と取得日を併記する |

現在の段階ではなく次の段階の規模を記載する理由は、設計よりも先に規模が変更されるためである。
