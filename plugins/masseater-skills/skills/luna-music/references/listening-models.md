# 音声を入力できるモデルで「聴く」ときの扱い

2026-11-28 に、クラウドから使える音声入力のモデルを調べて試した。結論は、`@cf/cloudflare/clef-omni` は音の有無と大まかな種類しか答えられず、リズムの細部には使えない、である。

## クラウドから使える経路

- Workers AI のモデルで音声（WAV か MP3）を受け取るのは `@cf/cloudflare/clef-omni` だけである。Clef は決定モデルで、yes・no（`noul`）、選択（`choice`）、段階評価（`score`）の質問に確率で答える。音声は base64 の data URL で渡し、1 本あたり 8 MiB と 300 秒まで、1 回に 4 本までである。8 秒の音声が約 420 トークンで、費用は 1 回あたり 0.0001 ドルに満たない。
- Gemini は、Cloudflare の Unified Billing 経由で `google/gemini-3.8-flash` などを、既存の Cloudflare トークンだけで呼べる（`POST /accounts/<id>/ai/run`、Gemini 形式の `contents` に `inlineData` で音声を入れる）。ただしクレジットが 0 だと HTTP 402（`Insufficient unified billing credits`）で止まる。クレジットは AI Gateway のダッシュボードで持ち主がチャージする（5% の手数料がかかり、API では買えない）。ゲートウェイ `default` の 1 日の支出上限は 0.11 ドルなので、聴き比べ程度なら収まる。
- Flovia の `flovia_openai` と `flovia_minimax` は文字だけで、音声を入力できない。ほかの Flovia のツールと portal のサーバーにも、音声を聴くものはない。BYOK のプロバイダーキーはゲートウェイに登録されていない。gcloud はログインされていない。

## 校正の結果

聴かせる前に、答えが正解に追従するかを、正解が分かっている音で必ず確かめる。`/mnt/project-files/luna-ukg/` の `render.mjs` が、サンプルから条件を変えたループを書き出す。

- ハットだけのループで、1 拍あたり 2 発、4 発、8 発の 3 種類を聴かせたところ、どれも「4 発より多い」に 0.6〜0.83 の確率を割り当てた。
- 奇数番のハットを 0 と 0.5 ステップ遅らせても、スウィングの段階評価は 0.14 と 0.20 で、ほぼ同じだった。
- ハットを全部抜いたループに「閉じたハットは聞こえるか」と尋ねても 0.64 だった。

したがって、ハットの並びやスウィングを Clef-omni の答えで確定してはならない。使ってよいのは、鳴っているかどうかの大づかみな確認（ドラムがあるか、歌声が混ざっていないか）に限る。

## 手順

0. REST で呼ぶときは、ヘッダーに `cf-aig-gateway-id: default` と `cf-aig-metadata`（`{"tool":"luna-music"}`）を付ける。2026-11-28 の試行は付けずに呼び、clef-omni を10回、ゲートウェイを通さずに使った（上限が掛からない）。

1. 聴かせる音は、書き出した 16 ビットのモノラル WAV にする。区間は 8 秒前後に切る。
2. 質問する前に、正解を変えた対照の音を作って同じ質問をし、答えが正解に追従することを確かめる。追従しない質問の答えは、報告に使わない。
3. 追従しない項目は「推定のまま」と報告する。持ち主が聴いて決める項目として残す。
4. 音声を聴けるモデルが使えるようになったら（Gemini のクレジットがチャージされたら）、同じ対照の音で校正してから使う。ハットの並びとスウィングは、モデルに聴かせる前に [`separate-drums`](separate-drums.md) の測定で出す。
